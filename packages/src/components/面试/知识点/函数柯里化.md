我们逐步分析 `curry` 函数的执行过程，以 `curriedAdd(1)(2)(3)` 和 `curriedAdd(1, 2)(3)` 为例。

---

## 1. 柯里化函数的定义

```javascript
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return function(...more) {
      return curried.apply(this, args.concat(more));
    };
  };
}
```

- `fn` 是需要被柯里化的函数，这里 `fn = (a, b, c) => a + b + c`，它的 `fn.length` 是 3。
- `curry` 返回一个函数 `curried`，它接收任意数量的参数（`...args`）。

---

## 2. 执行 `curriedAdd(1)(2)(3)`

### 第一步：`curriedAdd(1)`
- `curriedAdd` 就是 `curried` 函数。
- 调用 `curried(1)`，此时 `args = [1]`。
- 判断 `args.length >= fn.length`？ `1 >= 3` 为假，所以进入 `else` 分支。
- 返回一个新函数：`function(...more) { return curried.apply(this, args.concat(more)); }`。
- 这个新函数捕获了闭包中的 `args = [1]` 和 `curried` 引用。我们称这个返回的函数为 `step2`。

### 第二步：`step2(2)`（即 `curriedAdd(1)(2)`）
- 调用 `step2(2)`，此时 `more = [2]`。
- `step2` 内部执行 `curried.apply(this, args.concat(more))`，其中 `args` 是上一步的 `[1]`，`args.concat(more) = [1, 2]`。
- 因此等价于调用 `curried(1, 2)`。
- 进入 `curried` 函数（又是同一个 curried），参数 `args = [1, 2]`。
- 判断 `args.length >= fn.length`？ `2 >= 3` 为假，再次进入 else 分支。
- 返回一个新函数：`function(...more) { return curried.apply(this, args.concat(more)); }`，此时闭包捕获的 `args = [1, 2]`。称这个返回函数为 `step3`。

### 第三步：`step3(3)`（即 `curriedAdd(1)(2)(3)`）
- 调用 `step3(3)`，`more = [3]`。
- 内部执行 `curried.apply(this, args.concat(more))`，`args = [1, 2]`，拼接后为 `[1, 2, 3]`。
- 等价于调用 `curried(1, 2, 3)`。
- 进入 `curried`，此时 `args = [1, 2, 3]`。
- 判断 `args.length >= fn.length`？ `3 >= 3` 为真，所以执行 `fn.apply(this, args)`。
- `fn` 是 `(a,b,c) => a+b+c`，用参数 `1,2,3` 调用，得到结果 `6`。
- 这个结果被逐层返回：`step3` 返回 6，`step2` 得到 6 并返回，`curriedAdd(1)` 最终也得到 6。

所以最终结果是 6。

---

## 3. 执行 `curriedAdd(1, 2)(3)`

### 第一步：`curriedAdd(1, 2)`
- 调用 `curried(1, 2)`，`args = [1, 2]`。
- `args.length = 2 < 3`，返回一个新函数 `function(...more) { return curried.apply(this, args.concat(more)); }`，闭包捕获 `args = [1, 2]`。称这个函数为 `step2`。

### 第二步：`step2(3)`
- 调用 `step2(3)`，`more = [3]`。
- 内部执行 `curried.apply(this, [1, 2].concat([3]))` → `curried(1, 2, 3)`。
- 进入 `curried`，`args = [1, 2, 3]`，长度等于 3，满足条件，调用 `fn(1,2,3)` 返回 6。
- 6 返回给 `step2`，然后作为 `curriedAdd(1, 2)(3)` 的结果。

因此结果也是 6。

---

## 4. 关键点总结

- **`fn.length`** 用于确定原函数期望的参数总数。
- **闭包**：每次返回的新函数都持有当前累积的参数 `args`，以及对外部 `curried` 函数的引用。
- **递归调用**：通过 `curried.apply(this, args.concat(more))` 将新参数拼接到已有参数上，再次调用 `curried` 进行判断。
- **`apply(this, ...)`** 是为了保留调用时的 `this` 上下文，虽然此处没有用到，但保证了通用性。

这种柯里化实现支持**任意参数数量**的调用方式，只要最终参数总数达到 `fn.length` 就执行原函数，否则继续返回新函数等待剩余参数。



下面通过一个例子来说明 `apply(this, ...)` 的作用：它确保在柯里化过程中，原始函数 `fn` 能够访问正确的 `this` 上下文，尤其是在函数被作为对象方法调用时。

---

## 示例场景

假设有一个计算器对象，它有一个系数 `factor`，我们想定义一个计算乘积的方法，该方法依赖于 `this.factor`：

```javascript
const calculator = {
  factor: 10,
  multiply(a, b) {
    return (a + b) * this.factor;
  }
};
```

现在我们对 `multiply` 进行柯里化，并希望它能作为对象的方法调用：

```javascript
const curriedMultiply = curry(calculator.multiply);

// 预期：固定第一个参数为 2，然后传入第二个参数 3，得到 (2+3)*10 = 50
const partial = curriedMultiply(2);
const result = partial(3); 
console.log(result); // 预期 50
```

---

## 如果不保留 `this`（假设 `apply(this, ...)` 被替换为 `fn(...args)`）

如果 `curry` 内部没有使用 `apply(this, ...)` 来传递 `this`，而是直接调用 `fn(...args)`，那么 `fn` 内部的 `this` 就会丢失，导致错误：

```javascript
function brokenCurry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn(...args); // 这里丢失了 this
    }
    return function(...more) {
      return curried(...args.concat(more)); // 这里也丢失了 this
    };
  };
}

const curriedBroken = brokenCurry(calculator.multiply);
const partialBroken = curriedBroken(2);
console.log(partialBroken(3)); 
// 报错：Cannot read property 'factor' of undefined
// 因为 multiply 内部的 this 是 undefined
```

---

## 保留 `this` 的正确实现

原 `curry` 实现通过 `apply(this, args)` 将当前调用时的 `this` 传递给原始函数，并且在返回的函数中也使用 `apply(this, ...)` 来传递 `this`。

```javascript
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args); // 保留 this
    }
    return function(...more) {
      return curried.apply(this, args.concat(more)); // 保留 this
    };
  };
}

const curriedCorrect = curry(calculator.multiply);
const partialCorrect = curriedCorrect(2);
console.log(partialCorrect(3)); // 输出 50，正确
```

**执行步骤**：

1. `curriedCorrect(2)` 调用时，`this` 是全局对象（因为是直接调用）。但此时返回的闭包会捕获这个 `this`，不过重要的是后续调用时 `this` 会被传递。
2. `partialCorrect(3)` 调用时，它是作为独立函数调用的，`this` 是全局对象（严格模式下是 `undefined`）。但关键在于，当我们真正执行 `fn.apply(this, args)` 时，`this` 是什么？
   - 注意：`partialCorrect` 是由 `curriedCorrect` 返回的函数，它的 `this` 在调用时被确定。如果我们希望 `multiply` 内部能访问 `calculator`，就需要在调用 `partialCorrect` 时通过某种方式绑定 `this`，例如使用 `call` 或 `apply`，或者将函数绑定为对象的方法。

然而，上面的例子中 `partialCorrect(3)` 直接调用，`this` 仍然是全局对象，所以 `multiply` 内部的 `this.factor` 依然是 `undefined` 吗？  
实际上，原 `curry` 的实现中，**只有在最终调用原始函数 `fn` 时**才使用 `apply(this, args)`，这个 `this` 来自于最后一次调用 `curried` 时的上下文。如果我们希望 `multiply` 内部的 `this` 指向 `calculator`，我们需要在调用 `curriedMultiply` 或它的返回函数时，确保 `this` 被正确设置。

例如，我们可以这样使用：

```javascript
// 将 curriedMultiply 绑定为 calculator 的方法
const boundCurried = curriedCorrect.bind(calculator);
const partialBound = boundCurried(2);
console.log(partialBound(3)); // 输出 50

// 或者直接通过对象调用
calculator.curriedMultiply = curriedCorrect;
const partialObj = calculator.curriedMultiply(2);
console.log(partialObj(3)); // 输出 50，因为调用 calculator.curriedMultiply(2) 时 this 就是 calculator
```

如果我们将柯里化函数作为对象的方法调用，或者使用 `bind`/`call`/`apply` 手动绑定 `this`，那么原始函数 `multiply` 就能正确获取到 `this.factor`。

---

## 结论

`apply(this, ...)` 保证了柯里化函数能够将调用时的 `this` 上下文一直传递到原始函数，使得柯里化后的函数可以被用作对象方法、通过 `bind` 绑定，或在类实例中使用，而不会丢失 `this`。这种通用性让柯里化函数更加灵活，能适应更多场景。
