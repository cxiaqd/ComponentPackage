函数柯里化的核心是**将多参数函数转换为一系列单参数函数，并能够“记住”已传入的参数，直到所有参数收集完毕再执行**。这个“记住”已传入参数的能力，正是通过闭包实现的。

---

### 一、闭包在柯里化中的作用

```javascript
function curry(fn) {
  // 1. 外层函数执行时，创建闭包环境
  const arity = fn.length;
  const args = [];   // 私有变量，用于存储已收集的参数
  
  return function curried(...newArgs) {
    // 2. 内层函数通过闭包访问 args 和 arity
    args.push(...newArgs);
    
    if (args.length >= arity) {
      // 参数足够，执行原函数
      return fn(...args);
    } else {
      // 参数不足，返回一个等待更多参数的函数
      return curried;
    }
  };
}

const add = (a, b, c) => a + b + c;
const curriedAdd = curry(add);

curriedAdd(1)(2)(3); // 6
```

**过程**：
1. 调用 `curry(add)` 时，创建了闭包环境，其中保存了 `args` 数组和 `arity`。
2. `curriedAdd(1)` 返回一个新的函数（实际上就是 `curried` 自身），但此时 `args` 变为 `[1]`。
3. 再次调用这个返回的函数 `(2)`，`args` 变为 `[1, 2]`，仍然返回 `curried`。
4. 第三次调用 `(3)`，`args` 变为 `[1, 2, 3]`，长度达到 `arity`，执行原函数并返回结果。

---

### 二、为什么必须用闭包？

如果没有闭包，函数执行完毕后其内部变量会被垃圾回收，无法保留已收集的参数。柯里化需要**跨多次调用持续累积参数**，这要求函数在返回后仍然能够访问到上一次调用时的状态。

**闭包恰好提供了这种持久化的词法环境**——内部函数（每次调用返回的函数）引用外部函数的变量，使得这些变量不会被销毁。

---

### 三、替代方案（本质仍是闭包）

即使使用对象存储参数，也离不开闭包：

```javascript
function curry(fn) {
  const arity = fn.length;
  const context = { args: [] }; // 对象存储参数
  return function curried(...newArgs) {
    context.args.push(...newArgs);
    if (context.args.length >= arity) {
      return fn(...context.args);
    }
    return curried;
  };
}
```

这里 `context` 对象虽然显式存在，但仍然是闭包的一部分（内部函数引用了外部函数的 `context` 变量）。本质上没有摆脱闭包。

---

### 四、闭包带来的好处

1. **状态封装**：已传入的参数对外部不可见，避免了污染。
2. **惰性执行**：只有参数足够时才真正执行原函数，实现函数式编程的延迟求值。
3. **可重用性**：柯里化后的函数可以分步传递参数，例如 `const addOne = curriedAdd(1);` 后续调用 `addOne(2)(3)`。

---

### 五、小结

**函数柯里化使用闭包，是因为闭包能够“记住”函数多次调用之间累积的状态（已传入的参数）。** 这种能力使得我们可以将多参数函数分解为一系列可逐步填充参数的函数链，从而实现参数复用、延迟执行和函数组合。
