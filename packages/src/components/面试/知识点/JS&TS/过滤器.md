在 Vue 2 中，**filters（过滤器）** 是一种用于**文本格式化**的便捷功能。它的核心作用是在不修改原始数据的情况下，对视图（模板）中展示的数据进行格式化处理。

以下是关于 Vue 2 过滤器的详细解析：

### 1. 过滤器的作用

过滤器主要用于**轻量级的文本转换**，例如：

-   将时间戳格式化为 `YYYY-MM-DD`。
-   将英文字符串首字母大写。
-   将数字格式化为货币形式（如 `12345` -> `$12,345`）。
-   对文本进行截断处理。

**核心原则：** 过滤器**不会改变原数据**，它只是返回处理后的版本用于渲染。

### 2. 定义方式

过滤器有两种定义方式：**全局**和**局部**。

#### 全局过滤器
在创建 Vue 实例之前，通过 `Vue.filter()` 定义，可以在任何组件中使用。

```javascript
// main.js 或入口文件
import Vue from 'vue';

Vue.filter('capitalize', function (value) {
  if (!value) return '';
  value = value.toString();
  return value.charAt(0).toUpperCase() + value.slice(1);
});
```

#### 局部过滤器
在组件的 `filters` 选项中定义，仅限当前组件使用。

```vue
<template>
  <div>{{ message | capitalize }}</div>
</template>

<script>
export default {
  data() {
    return {
      message: 'hello world'
    };
  },
  filters: {
    capitalize: function (value) {
      if (!value) return '';
      value = value.toString();
      return value.charAt(0).toUpperCase() + value.slice(1);
    }
  }
};
</script>
```

### 3. 使用方式

过滤器主要在 **Mustache 插值** (`{{ }}) 和 **`v-bind` 表达式**中使用。

#### 基本用法

```html
<!-- 单个过滤器 -->
<p>{{ price | currency }}</p>

<!-- 串联过滤器（从左到右执行） -->
<!-- 相当于：formatDate( uppercase( date ) ) -->
<p>{{ date | uppercase | formatDate }}</p>

<!-- 带参数（冒号后传参） -->
<!-- 相当于：filterText( message, 'arg1', 'arg2' ) -->
<p>{{ message | filterText('arg1', 'arg2') }}</p>
```

#### 在 `v-bind` 中使用
```html
<div v-bind:id="rawId | formatId"></div>
```

### 4. 过滤器的原理

过滤器的本质是一个**JavaScript 函数**。

-   **第一个参数**：始终是传入的原始值（管道符 `|` 左边的值）。
-   **后续参数**：在过滤器名后通过冒号 `:` 传入的参数。
-   **返回值**：函数返回什么，模板中就渲染什么。

**注意：** 过滤器内不能通过 `this` 访问 Vue 实例的数据或方法（Vue 3 中彻底移除了 `this` 上下文，Vue 2 中虽然有 `this` 但指向的是全局对象或 `undefined`，**不应依赖 `this`**）。

### 5. 使用场景与局限性

#### ✅ 适合使用过滤器的场景
-   **简单的数据格式化**：日期格式化、货币转换、首字母大写。
-   **与 `v-for` 配合**：对列表中的每一项进行统一处理。
-   **与 `v-model` 配合（借助计算属性）**：虽然不能直接用于 `v-model`，但可以结合 `input` 事件手动触发格式化。

#### ❌ 局限性
1.  **不能在计算属性或方法中直接复用**：过滤器只能在模板中使用。如果你需要在 JavaScript 逻辑中使用相同的格式化逻辑，你需要将过滤器函数抽取为公共函数（Utils），同时保留过滤器作为模板的语法糖。
2.  **性能**：过滤器在每次渲染更新时都会执行。如果逻辑较重，建议使用**计算属性**（如果依赖响应式数据）或**方法**。
3.  **逻辑复杂度**：对于复杂的业务逻辑，过滤器会使模板变得难以维护，此时应优先使用**计算属性**。

### 6. 过滤器 vs 计算属性 vs 方法

| 特性 | Filters | Computed | Methods |
| :--- | :--- | :--- | :--- |
| **使用场景** | 简单的文本格式化（模板专用） | 依赖其他响应式数据的复杂逻辑 | 事件处理或主动调用 |
| **缓存** | 无（每次渲染都执行） | **有**（基于依赖缓存） | 无 |
| **可传参** | 支持（`value \| filter(arg)`） | 不支持（需返回函数，较复杂） | 支持 |
| **访问 this** | **不支持**（不应依赖） | 支持 | 支持 |
| **适用范围** | 模板 `{{}}` 和 `v-bind` | 模板、`data`、`methods` 等 | 任何地方 |

### 7. Vue 3 的重大变更（迁移注意）

如果你正在学习 Vue 2，需要注意：**Vue 3 已经移除了 filters**。

在 Vue 3 中，官方推荐使用 **方法调用** 或 **计算属性** 来替代过滤器。

**Vue 3 迁移示例：**
```html
<!-- Vue 2 -->
<p>{{ price | currency }}</p>

<!-- Vue 3 推荐做法 -->
<p>{{ currency(price) }}</p>
<!-- 或者 -->
<p>{{ formattedPrice }}</p> <!-- 使用计算属性 -->
```

### 总结

在 Vue 2 中，过滤器提供了一种**声明式**的文本格式化方式，让模板看起来更优雅。但它的能力有限，主要适用于简单、无副作用的纯函数转换。对于复杂的逻辑，建议优先选择**计算属性**；如果项目准备升级 Vue 3，建议开始习惯用**方法**来替代过滤器，以减少迁移成本。
