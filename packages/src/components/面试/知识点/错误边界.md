Vue 中没有像 React 那样内置的 `<ErrorBoundary>` 组件，但可以通过 **`errorCaptured`** 生命周期钩子（Vue 2）或 **`onErrorCaptured`** 函数（Vue 3）来实现相同的错误边界功能。它的作用是**捕获子组件树中抛出的错误**，阻止错误向上冒泡导致整个应用崩溃，并允许你展示一个备用的 fallback UI。

## 核心概念

错误边界本质上是一个 Vue 组件，它利用 `errorCaptured` / `onErrorCaptured` 钩子来“监听”其子组件中发生的错误。当子组件或更深层的子孙组件在渲染、生命周期函数或事件处理中抛出错误时，这个钩子就会被触发。

**它的主要作用包括：**
- **错误隔离**：将错误限制在局部组件内，防止整个页面白屏
- **降级体验**：当某个模块出错时，展示友好的错误提示，而不是让用户面对控制台报错
- **集中处理**：在错误边界中可以统一进行错误上报、日志记录等操作

## 技术实现

### Vue 2 写法（errorCaptured）

在父组件中定义 `errorCaptured` 钩子，它会接收三个参数：错误对象、发生错误的组件实例、以及错误信息字符串。

```vue
<!-- ErrorBoundary.vue (Vue 2) -->
<template>
  <div>
    <!-- 如果有错误，展示 fallback UI；否则正常渲染子组件 -->
    <div v-if="hasError" class="error-fallback">
      <h3>⚠️ 出错了</h3>
      <p>{{ errorMessage }}</p>
      <button @click="resetError">重试</button>
    </div>
    <slot v-else></slot>
  </div>
</template>

<script>
export default {
  data() {
    return {
      hasError: false,
      errorMessage: ''
    }
  },
  errorCaptured(err, vm, info) {
    // 捕获到子组件错误时触发
    this.hasError = true
    this.errorMessage = err.message || '组件加载失败'
    
    // 上报错误到监控系统
    console.error('[ErrorBoundary]', err, info)
    
    // 返回 false 可以阻止错误继续向上冒泡
    // 如果返回 true，错误会继续传播到父组件的 errorCaptured
    return false
  },
  methods: {
    resetError() {
      this.hasError = false
      this.errorMessage = ''
      // 可选：重新渲染子组件
      this.$forceUpdate()
    }
  }
}
</script>
```

### Vue 3 写法（onErrorCaptured）

Vue 3 中，`errorCaptured` 被重命名为 `onErrorCaptured`，并在 Composition API 中使用。参数相同，但多了一个 `instance` 参数（发生错误的组件实例）。

```vue
<!-- ErrorBoundary.vue (Vue 3) -->
<template>
  <div v-if="hasError" class="error-fallback">
    <h3>⚠️ 出错了</h3>
    <p>{{ errorMessage }}</p>
    <button @click="resetError">重试</button>
  </div>
  <slot v-else></slot>
</template>

<script setup>
import { ref, onErrorCaptured } from 'vue'

const hasError = ref(false)
const errorMessage = ref('')

onErrorCaptured((err, instance, info) => {
  // 捕获子组件错误
  hasError.value = true
  errorMessage.value = err.message || '组件加载失败'
  
  // 错误上报
  console.error('[ErrorBoundary]', err, info)
  
  // 阻止错误继续传播
  return false
})

const resetError = () => {
  hasError.value = false
  errorMessage.value = ''
}
</script>
```

### 使用错误边界组件

将可能出错的组件包裹在错误边界内部：

```vue
<template>
  <div class="dashboard">
    <!-- 每个独立模块都有自己的错误边界，互不影响 -->
    <ErrorBoundary>
      <UserStatsWidget :userId="userId" />
    </ErrorBoundary>

    <ErrorBoundary>
      <RecentActivityWidget :userId="userId" />
    </ErrorBoundary>

    <ErrorBoundary>
      <NotificationsWidget />
    </ErrorBoundary>
    
    <!-- 这个组件即使出错，也不会影响上面的组件 -->
    <Footer />
  </div>
</template>
```

## 使用建议

1. **尽量细化包裹范围**  
   为每个独立功能模块单独设置错误边界（如侧边栏、评论区、数据图表），而不是把整个页面包在一个错误边界里。这样当某个模块出错时，其他模块依然正常工作。

2. **提供恢复机制**  
   在 fallback UI 中提供一个“重试”按钮，让用户可以手动恢复，提升体验。

3. **记录错误信息**  
   在 `errorCaptured` 中调用错误上报服务（如 Sentry），方便定位生产环境问题。

4. **区分版本差异**  
   - Vue 2：使用 `errorCaptured` 选项
   - Vue 3：使用 `onErrorCaptured` 组合式函数

## 注意事项

- **只能捕获子组件错误**：`errorCaptured` / `onErrorCaptured` 只捕获其子组件树中的错误，不捕获自身模板或生命周期中的错误。
- **不影响全局错误处理器**：即使使用了错误边界，`Vue.config.errorHandler` 仍然会收到错误（除非在边界中返回 `true` 阻止传播）。
- **异步错误**：`errorCaptured` 可以捕获异步操作（如 `setTimeout`）中抛出的错误吗？从 Vue 2.6 开始，它也能捕获来自 `async` 函数或 Promise 链的错误。

## 与全局 errorHandler 的区别

| 特性 | 错误边界 (errorCaptured) | 全局错误处理器 |
|------|-------------------------|----------------|
| 作用范围 | 特定组件树的子组件 | 整个应用的所有 Vue 错误 |
| 控制粒度 | 细粒度，可针对不同模块定制 | 粗粒度，统一处理 |
| UI 降级 | 可展示 fallback UI | 通常只做日志记录，不直接影响 UI |
| 推荐场景 | 关键业务模块、第三方组件包裹 | 兜底捕获、错误上报 |

两者通常配合使用：错误边界处理局部 UI 降级，全局处理器负责统一错误上报和兜底。
