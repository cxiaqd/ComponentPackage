## 1. 从输入URL到页面完全加载，中间发生了什么？

**考察点**：网络原理、浏览器渲染机制、性能优化意识

**参考答案要点**：
- **DNS解析**：浏览器缓存 → 系统缓存 → 路由器缓存 → 递归/迭代查询
- **TCP连接**：三次握手（SYN → SYN-ACK → ACK），现代常复用Keep-Alive或HTTP/2多路复用
- **TLS协商**（HTTPS）：四次握手，涉及非对称加密交换对称密钥
- **HTTP请求/响应**：构建请求头（缓存策略如`Cache-Control`、`If-Modified-Since`等），服务器返回状态码和资源
- **解析与渲染**：
  - HTML解析为DOM树，遇到`<script>`（尤其是无`async/defer`）会阻塞解析
  - CSS解析为CSSOM树，CSSOM构建完成前会阻塞渲染（避免无样式内容闪烁）
  - DOM + CSSOM → 渲染树（Render Tree），排除`display:none`等不可见元素
  - **布局（Layout）**：计算几何位置，重排触发点（如获取`offsetHeight`、窗口resize）
  - **绘制（Paint）**：填充像素，分层绘制
  - **合成（Composite）**：GPU合成图层，提升动画性能（`transform`、`opacity`）
- **关键优化点**：首屏关键CSS内联、`async/defer`加载脚本、减少重排、利用`will-change`提示合成层

**可延伸探讨**：谈谈如何量化首屏时间（FP、FCP、LCP），以及你项目中做的针对性优化。

## 2. 如何设计一个支持10万+数据量的列表渲染，确保滚动流畅且不卡顿？

**考察点**：性能优化、浏览器渲染机制、工程实现能力

**参考答案要点**：
在 Vue 中处理 **10 万+ 数据量的列表**并保证滚动流畅，核心思路是 **虚拟滚动（Virtual Scrolling）**——只渲染可视区域内的 DOM 节点，动态替换上下不可见区域的数据，从而将 DOM 节点数量控制在极小的范围内（通常几十个）。Vue 生态中有成熟的解决方案，也可以基于原生 API 自行实现。

---

## 1. 原理：虚拟滚动如何工作

- 容器固定高度，设置 `overflow: auto` 或 `overflow-y: scroll`。
- 在容器内放置一个占位元素（高度等于所有列表项总高度），用于撑开滚动条。
- 监听滚动事件，根据 `scrollTop` 计算当前可视区域的起始索引和结束索引。
- 只渲染索引区间内的数据项，使用绝对定位或 `transform: translateY` 将它们放置在正确位置。
- 当滚动时，动态更新渲染的数据，实现复用有限的 DOM 元素。

## 2. Vue 中实现虚拟滚动的方案

### 2.1 使用成熟第三方库（推荐）

#### vue-virtual-scroller（Vue 2 & Vue 3）
这是官方维护的库，支持多种模式（滚动、网格、无限加载等），性能稳定。

```bash
npm install vue-virtual-scroller
```

**基本用法：**

```vue
<template>
  <RecycleScroller
    class="scroller"
    :items="items"
    :item-size="50"      <!-- 每个项目固定高度 -->
    key-field="id"
    v-slot="{ item }"
  >
    <div class="item">{{ item.name }}</div>
  </RecycleScroller>
</template>

<script>
import { RecycleScroller } from 'vue-virtual-scroller'
import 'vue-virtual-scroller/dist/vue-virtual-scroller.css'

export default {
  components: { RecycleScroller },
  data() {
    return {
      items: [] // 10万+数据
    }
  },
  mounted() {
    // 模拟加载数据
    this.items = Array.from({ length: 100000 }, (_, i) => ({ id: i, name: `Item ${i}` }))
  }
}
</script>

<style scoped>
.scroller {
  height: 500px;
}
.item {
  height: 50px;
}
</style>
```

- `RecycleScroller`：复用 DOM 元素，支持动态高度。
- `DynamicScroller`：支持动态高度项目，但性能略低。
- 库会自动处理滚动性能、缓存、事件节流等。

#### 其他库
- **vue-virtual-scroll-list**（轻量，适合列表）
- **vxe-table**（表格场景）
- **vue3-virtual-scroll-list**（Vue 3 专用）

### 2.2 手动实现简易虚拟滚动（原理教学）

如果不想依赖库，可以自己实现核心逻辑，但生产环境建议使用成熟方案。

**示例结构：**

```vue
<template>
  <div ref="container" class="virtual-list" @scroll="onScroll">
    <!-- 占位，撑开滚动条 -->
    <div class="phantom" :style="{ height: totalHeight + 'px' }"></div>
    <!-- 实际渲染的列表 -->
    <div class="list" :style="{ transform: `translateY(${offsetY}px)` }">
      <div
        v-for="item in visibleItems"
        :key="item.id"
        class="list-item"
        :style="{ height: itemHeight + 'px' }"
      >
        {{ item.name }}
      </div>
    </div>
  </div>
</template>

<script>
export default {
  props: {
    items: Array,       // 大数据列表
    itemHeight: { type: Number, default: 50 } // 固定高度
  },
  data() {
    return {
      visibleStart: 0,
      visibleEnd: 0,
      containerHeight: 0
    }
  },
  computed: {
    totalHeight() {
      return this.items.length * this.itemHeight
    },
    visibleItems() {
      return this.items.slice(this.visibleStart, this.visibleEnd + 1)
    },
    offsetY() {
      return this.visibleStart * this.itemHeight
    }
  },
  mounted() {
    this.containerHeight = this.$refs.container.clientHeight
    this.updateVisibleRange()
    window.addEventListener('resize', this.onResize)
  },
  beforeDestroy() {
    window.removeEventListener('resize', this.onResize)
  },
  methods: {
    onScroll(e) {
      const scrollTop = e.target.scrollTop
      this.updateVisibleRange(scrollTop)
    },
    updateVisibleRange(scrollTop = 0) {
      const start = Math.floor(scrollTop / this.itemHeight)
      const end = Math.min(
        start + Math.ceil(this.containerHeight / this.itemHeight),
        this.items.length - 1
      )
      // 增加缓冲区，防止滚动时白屏
      const buffer = 5
      this.visibleStart = Math.max(0, start - buffer)
      this.visibleEnd = Math.min(this.items.length - 1, end + buffer)
    },
    onResize() {
      this.containerHeight = this.$refs.container.clientHeight
      this.updateVisibleRange(this.$refs.container.scrollTop)
    }
  }
}
</script>

<style scoped>
.virtual-list {
  position: relative;
  height: 500px;
  overflow-y: auto;
}
.phantom {
  position: absolute;
  top: 0;
  left: 0;
  right: 0;
  z-index: -1;
}
.list {
  position: absolute;
  top: 0;
  left: 0;
  right: 0;
}
.list-item {
  box-sizing: border-box;
  border-bottom: 1px solid #eee;
}
</style>
```

**关键点：**
- 使用 `phantom` 占位元素撑开滚动条，`list` 通过 `transform` 定位。
- 监听 `scroll` 事件，动态计算可见区域，使用 `slice` 截取数据。
- 加入缓冲区（buffer）避免快速滚动时出现空白。
- 使用 `requestAnimationFrame` 或节流优化滚动事件。

## 3. 进一步优化建议

### 3.1 动态高度处理
如果列表项高度不固定（如文本内容不同），需要使用更复杂的算法（如预估高度 + 缓存实际高度）。推荐直接使用 `vue-virtual-scroller` 的 `DynamicScroller` 组件，它会自动测量并缓存高度。

### 3.2 使用 `v-once` 或 `v-memo`（Vue 3）
对于列表项中不会变化的部分，使用 `v-once` 避免重复渲染；Vue 3 中可用 `v-memo` 缓存子树。

```vue
<div v-for="item in list" :key="item.id" v-memo="[item.id]">
  <!-- 只有当 item.id 变化时才重新渲染 -->
</div>
```

### 3.3 避免在 `v-for` 中使用复杂表达式或方法
在列表项中尽量使用计算属性或预先处理数据，减少每次渲染时的计算开销。

### 3.4 合理使用 `key`
必须为每个虚拟列表项提供稳定唯一的 `key`，帮助 Vue 复用 DOM 元素。

### 3.5 无限滚动与懒加载
对于 10 万+ 数据，通常不需要一次性加载所有数据，可以结合无限滚动（Intersection Observer）分批加载，进一步减少内存占用和首屏渲染压力。

```javascript
// 使用 Intersection Observer 监听滚动底部
// 加载下一页数据
```

### 3.6 开启 CSS 硬件加速
通过 `transform: translateZ(0)` 或 `will-change: transform` 提升滚动流畅度。

```css
.list {
  will-change: transform;
}
```

### 3.7 优化滚动事件
使用 `requestAnimationFrame` 或 `lodash.throttle` 限制滚动事件处理频率，避免过度计算。

```javascript
import { throttle } from 'lodash-es'

onScroll: throttle(function(e) {
  // 更新可视范围
}, 16) // 约 60fps
```

## 4. 性能对比：虚拟滚动 vs 全量渲染

| 方案 | DOM 节点数 | 内存占用 | 滚动流畅度 |
|------|-----------|---------|-----------|
| 全量渲染 10 万项 | 10 万+ | 极高 | 严重卡顿、崩溃 |
| 虚拟滚动（视口 500px，每项 50px） | 约 10~20 个 | 极低 | 丝滑流畅 |

## 5. 总结

在 Vue 中处理 10 万+ 数据列表的最优实践：
1. **首选 `vue-virtual-scroller` 库**，它已经处理了绝大多数边界情况和性能优化。
2. 若需自定义，遵循 **虚拟滚动** 的核心思想：只渲染可视区 + 缓冲区，动态替换数据。
3. 配合 **节流、缓存、key 优化、CSS 硬件加速** 等手段，确保滚动丝滑。
4. 考虑 **分页或无限滚动**，避免一次性加载全部数据到前端内存（虽然虚拟滚动已能承载大量数据，但传输和初始化仍会耗时）。

最终效果：即使在 10 万+ 数据量下，列表滚动也能保持 60fps 的流畅体验。

## 3. 说说你对React（或Vue）中“key”的理解，为什么不能用index作为key？

**考察点**：虚拟DOM原理、Diff算法、对框架底层的理解

**参考答案要点**：
- **key的作用**：帮助框架识别哪些元素改变了、添加了或删除了，用于优化Diff算法的复用效率
- **为什么不用index**：
  - 当列表顺序发生变化（排序、插入、删除）时，index对应的组件实例可能会错位，导致：
    - 本应复用的组件被销毁重建，损失性能
    - 组件内部状态（如输入框内容、动画状态）错乱
  - Diff算法在比较时，如果key相同且类型相同，会复用DOM节点；用index时，即使数据顺序变了，key对应的节点仍可能被错误复用
- **正确做法**：使用数据中唯一且稳定的标识（如`id`），若无则使用`uuid`或`nanoid`生成

**可延伸探讨**：手写一个简化的Diff算法思路，说明同层比较、双端对比等策略，加深对框架设计的理解。

## 5. 你如何理解“状态管理”？在什么场景下需要使用Redux/Zustand/Pinia？如何选择？

**考察点**：状态管理选型、架构设计能力、对响应式原理的理解

**参考答案要点**：
- **核心认知**：状态管理的本质是解决**跨组件通信**和**状态变化可预测性**的问题，尤其当应用复杂度上升时
- **选择决策**：
  - **组件内部状态**：`useState`/`ref` 足够
  - **跨组件传递**：`Context`/`provide-inject` 适合低频、不频繁变化的数据（主题、用户信息），但重渲染问题需注意（可拆分Context）
  - **复杂全局状态**：
    - **Redux**：强调单向数据流、不可变更新、中间件生态丰富（处理异步、日志），适合大型项目、多人协作场景
    - **Zustand**：轻量、API简洁、无需Provider，适合中小型项目或希望快速迭代的场景
    - **Pinia（Vue生态）**：设计更现代，去掉了mutations，TypeScript支持优秀，Vue官方推荐
  - **服务端状态**：若涉及缓存、请求去重、数据更新，应优先使用**React Query / TanStack Query / SWR**，而不是将服务端数据存入全局状态
- **核心原理**（以Redux为例）：
  - Store持有状态树，Action描述事件，Reducer纯函数根据Action更新状态
  - 中间件（如redux-thunk、redux-saga）拦截Action，处理副作用

**可延伸探讨**：手写一个简化版的Redux，理解createStore、combineReducers、中间件链式调用的实现。

## 8. 你如何处理前端安全相关的问题？比如XSS、CSRF？

**考察点**：安全意识、防御实践

**参考答案要点**：

**XSS（跨站脚本攻击）**：
- **反射型/存储型**：核心是不信任用户输入
  - 对用户输入进行**转义**（HTML实体编码、JS编码），使用`textContent`替代`innerHTML`
  - 使用框架时，React/Vue默认会对插值（`{}`、`{{}}`）进行转义，避免直接使用`v-html`或`dangerouslySetInnerHTML`
  - 如果必须插入HTML，使用**DOMPurify**进行清理
  - 设置**CSP（内容安全策略）**，限制脚本来源（`script-src 'self'`），可有效防御内联脚本执行

**CSRF（跨站请求伪造）**：
- 关键操作（支付、修改密码）使用**CSRF Token**：服务端生成随机token嵌入页面，请求时携带验证
- **SameSite Cookie**：设置`SameSite=Lax`或`Strict`，限制第三方请求携带Cookie
- 使用**双重Cookie验证**或**自定义请求头**（如`X-Requested-With`）

**其他安全措施**：
- 敏感信息不存localStorage（易被XSS窃取），优先存httpOnly Cookie
- HTTPS全站加密，防止中间人攻击
- 依赖库漏洞扫描：`npm audit`、Snyk等工具
- 点击劫持防护：设置`X-Frame-Options: DENY`

## 问题1延伸：如何量化首屏时间，以及项目中做的针对性优化

### 核心指标量化

**1. 关键时间指标**
- **FP (First Paint)**：首次绘制时间，页面开始有视觉变化（背景色、骨架屏）
- **FCP (First Contentful Paint)**：首次内容绘制，DOM内容首次渲染（文本、图片等）
- **LCP (Largest Contentful Paint)**：最大内容绘制，视口内最大元素渲染完成时间，核心用户体验指标
- **TTI (Time to Interactive)**：页面可交互时间，主线程空闲且能响应用户操作

**2. 获取方式**
```javascript

      // 上报到监控平台
    }
  }
});
observer.observe({ entryTypes: ['paint'] });

// LCP 监听
```

### 实际项目优化案例

**场景**：某电商首页，优化前 LCP 4.2s，目标 2.5s 以内

**优化措施**：
1. **关键CSS内联**：提取首屏CSS（<14KB）内联到`<head>`，非关键CSS异步加载
   ```html
   <style>/* 首屏关键样式 */</style>
   <link rel="preload" href="non-critical.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
   ```

2. **图片优化**：
   - 使用 `<picture>` 元素提供 WebP 格式降级
   - 实现**渐进式图片加载**：先显示低质量模糊图，再替换高清图

3. **资源加载策略**：

   ```html
   <!-- 预加载关键资源 -->
   ```

## 问题2延伸：虚拟滚动中动态高度的处理方案

### 核心挑战
固定高度的虚拟滚动实现简单，但实际业务中列表项高度常是动态的（文本换行、图片加载后撑高、不同内容类型）。

### 解决方案架构

**1. 位置缓存 + 二分查找**
```typescript
class DynamicHeightVirtualList {
  private positions: number[] = []; // 存储每一项的顶部位置
  private sizes: number[] = [];      // 存储每一项的高度
  
  // 二分查找起始索引
  private findStartIndex(scrollTop: number): number {
    let low = 0, high = this.positions.length - 1;
    while (low <= high) {
      const mid = Math.floor((low + high) / 2);
      if (this.positions[mid] < scrollTop) {
        low = mid + 1;
      } else {
        high = mid - 1;
      }
    }
    return Math.max(0, low - 1);
  }
  
  // 更新单项高度
  updateItemSize(index: number, newHeight: number) {
    const oldHeight = this.sizes[index];
    const diff = newHeight - oldHeight;
    if (diff === 0) return;
    
    this.sizes[index] = newHeight;
    // 更新后续所有项的位置
    for (let i = index + 1; i < this.positions.length; i++) {
      this.positions[i] += diff;
    }
    // 触发重新渲染
  }
}
```

**2. ResizeObserver 监听高度变化**
```javascript
useEffect(() => {
  const resizeObserver = new ResizeObserver((entries) => {
    for (const entry of entries) {
      const { height } = entry.contentRect;
      const index = parseInt(entry.target.dataset.index);
      // 高度变化时更新缓存
      updateItemSize(index, height);
    }
  });
  
  // 观察所有渲染的列表项
  items.forEach(item => resizeObserver.observe(item));
  return () => resizeObserver.disconnect();
}, []);
```

**3. 性能优化策略**
- **异步批量更新**：使用 `requestIdleCallback` 在空闲时重新计算位置
- **预估高度策略**：设置默认预估高度（如50px），渲染后校正，减少重计算次数
- **增量更新**：只更新可见区域及缓存区的高度变化

**4. 开源方案参考**
- **react-virtualized** 的 `CellMeasurer`
- **vue-virtual-scroller** 的动态高度支持
- **tanstack-virtual** 提供的动态高度 API

## 问题3延伸：手写简化的Diff算法思路

### 核心原理：同层比较 + 双端对比

```typescript
// 简化版虚拟DOM Diff
function diff(oldVNode, newVNode, parentDom, index = 0) {
  // 1. 节点类型不同：直接替换
  if (oldVNode.type !== newVNode.type) {
    const newDom = createDom(newVNode);
    parentDom.replaceChild(newDom, parentDom.childNodes[index]);
    return;
  }
  
  // 2. 文本节点：更新内容
  if (typeof oldVNode.type === 'undefined') {
    if (oldVNode.text !== newVNode.text) {
      parentDom.childNodes[index].textContent = newVNode.text;
    }
    return;
  }
  
  // 3. 同类型元素：复用DOM，更新属性
  const dom = parentDom.childNodes[index];
  updateAttributes(dom, oldVNode.props, newVNode.props);
  
  // 4. 子节点Diff（核心）
  const oldChildren = oldVNode.children || [];
  const newChildren = newVNode.children || [];
  
  // 双端对比算法（简化）
  let oldStart = 0, oldEnd = oldChildren.length - 1;
  let newStart = 0, newEnd = newChildren.length - 1;
  let oldStartVNode, oldEndVNode, newStartVNode, newEndVNode;
  
  while (oldStart <= oldEnd && newStart <= newEnd) {
    oldStartVNode = oldChildren[oldStart];
    oldEndVNode = oldChildren[oldEnd];
    newStartVNode = newChildren[newStart];
    newEndVNode = newChildren[newEnd];
    
    // 相同key且相同类型，递归diff
    if (oldStartVNode.key === newStartVNode.key) {
      diff(oldStartVNode, newStartVNode, dom, oldStart);
      oldStart++; newStart++;
    } 
    else if (oldEndVNode.key === newEndVNode.key) {
      diff(oldEndVNode, newEndVNode, dom, oldEnd);
      oldEnd--; newEnd--;
    }
    // 旧头对上了新尾（节点移动）
    else if (oldStartVNode.key === newEndVNode.key) {
      diff(oldStartVNode, newEndVNode, dom, oldStart);
      // 移动DOM节点到最后
      dom.insertBefore(dom.childNodes[oldStart], dom.childNodes[oldEnd + 1]);
      oldStart++; newEnd--;
    }
    // 旧尾对上了新头
    else if (oldEndVNode.key === newStartVNode.key) {
      diff(oldEndVNode, newStartVNode, dom, oldEnd);
      dom.insertBefore(dom.childNodes[oldEnd], dom.childNodes[oldStart]);
      oldEnd--; newStart++;
    }
    else {
      // 找不到复用，创建新节点
      const newDom = createDom(newStartVNode);
      dom.insertBefore(newDom, dom.childNodes[oldStart]);
      newStart++;
    }
  }
  
  // 删除多余旧节点
  while (oldStart <= oldEnd) {
    dom.removeChild(dom.childNodes[oldStart]);
    oldStart++;
  }
  
  // 添加新节点
  while (newStart <= newEnd) {
    const newDom = createDom(newChildren[newStart]);
    dom.appendChild(newDom);
    newStart++;
  }
}
```

**关键优化点**：
- **key的作用**：通过key快速定位可复用的节点，避免不必要的DOM操作
- **为什么index不行**：列表重排时，index会变化，导致误判节点可复用，引发状态错乱
- **双端对比**：相比简单的顺序对比，能更好地处理节点移动场景，减少DOM操作

## 问题5延伸：手写简化版 Redux

### 核心实现：createStore + combineReducers + 中间件

```typescript
// 1. createStore 实现
function createStore(reducer, preloadedState, enhancer) {
  if (enhancer) {
    return enhancer(createStore)(reducer, preloadedState);
  }
  
  let currentState = preloadedState;
  let currentReducer = reducer;
  let listeners: (() => void)[] = [];
  
  function getState() {
    return currentState;
  }
  
  function dispatch(action) {
    // 执行 reducer 更新状态
    currentState = currentReducer(currentState, action);
    // 通知所有订阅者
    listeners.forEach(listener => listener());
    return action;
  }
  
  function subscribe(listener) {
    listeners.push(listener);
    // 返回取消订阅函数
    return () => {
      listeners = listeners.filter(l => l !== listener);
    };
  }
  
  // 初始化状态
  dispatch({ type: '@@redux/INIT' });
  
  return { getState, dispatch, subscribe };
}

// 2. combineReducers 实现
function combineReducers(reducers) {
  return function combination(state = {}, action) {
    const nextState = {};
    let hasChanged = false;
    
    for (const key in reducers) {
      const reducer = reducers[key];
      const previousStateForKey = state[key];
      const nextStateForKey = reducer(previousStateForKey, action);
      nextState[key] = nextStateForKey;
      hasChanged = hasChanged || nextStateForKey !== previousStateForKey;
    }
    
    return hasChanged ? nextState : state;
  };
}

// 3. 中间件实现（applyMiddleware）
function applyMiddleware(...middlewares) {
  return (createStore) => (reducer, preloadedState) => {
    const store = createStore(reducer, preloadedState);
    let dispatch = () => {
      throw new Error('中间件构建中');
    };
    
    const middlewareAPI = {
      getState: store.getState,
      dispatch: (action) => dispatch(action)
    };
    
    // 传入 middlewareAPI，获取第一层函数
    const chain = middlewares.map(middleware => middleware(middlewareAPI));
    // 组合中间件，增强 dispatch
    dispatch = compose(...chain)(store.dispatch);
    
    return {
      ...store,
      dispatch
    };
  };
}

// 4. compose 工具函数（函数组合）
function compose(...funcs) {
  if (funcs.length === 0) return arg => arg;
  if (funcs.length === 1) return funcs[0];
  
  return funcs.reduce((a, b) => (...args) => a(b(...args)));
}

// 5. 中间件示例：redux-thunk 实现
function thunkMiddleware({ dispatch, getState }) {
  return next => action => {
    if (typeof action === 'function') {
      return action(dispatch, getState);
    }
    return next(action);
  };
}

// 使用示例
const rootReducer = combineReducers({
  count: (state = 0, action) => {
    if (action.type === 'INCREMENT') return state + 1;
    return state;
  }
});

const store = createStore(
  rootReducer,
  { count: 0 },
  applyMiddleware(thunkMiddleware)
);

// 支持异步 action
store.dispatch(async (dispatch) => {
  const data = await fetch('/api/data');
  dispatch({ type: 'INCREMENT' });
});
```

**核心理解**：
- **纯函数**：reducer 必须无副作用，保证可预测性
- **中间件**：洋葱圈模型，每个中间件可以拦截、转换、延迟 action
- **不可变性**：reducer 中通过对象展开或 Immer 实现不可变更新

**3. 工具辅助**
```bash
# 使用 ts-migrate 自动迁移
npx ts-migrate-full .
```

**4. 常见问题处理**
- **第三方库无类型**：使用 `@types/` 或自定义声明
  ```typescript
  // declarations.d.ts
  declare module 'legacy-lib' {
    export function doSomething(param: any): void;
  }
  ```
- **动态 require**：改用 `import` 或添加类型断言
- **复杂的 this 绑定**：使用箭头函数或显式 `this` 参数

**迁移成果**：6周内完成 80% 核心代码覆盖，上线后因类型错误导致的 bug 减少 60%

## 问题7延伸：Webpack loader 和 plugin 原理对比

### Loader 原理

**本质**：转换器，将非 JS 模块转换为有效模块

```javascript
// 一个简单的 loader 实现
module.exports = function(source) {
  // source 是文件原始内容（Buffer 或 String）
  const options = this.getOptions(); // 获取配置选项
  
  // 进行转换处理
  const transformed = source.replace(/console\.log\(.*?\);?/g, '');
  
  // 返回处理后的代码
  return `export default ${JSON.stringify(transformed)}`;
  
  // 或者异步处理
  // const callback = this.async();
  // setTimeout(() => callback(null, transformed), 100);
};
```

**Loader 执行顺序**：从右到左，从下到上
```javascript
{
  module: {
    rules: [
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader', 'postcss-loader']
        // 执行顺序：postcss-loader → css-loader → style-loader
      }
    ]
  }
}
```

### Plugin 原理

**本质**：基于 Tapable 的事件钩子系统，在构建生命周期中注入自定义行为

```javascript
// 一个简单的 plugin 实现
class MyPlugin {
  apply(compiler) {
    // 监听编译完成事件
    compiler.hooks.done.tap('MyPlugin', (stats) => {
      console.log('编译完成！');
      console.log(`耗时: ${stats.endTime - stats.startTime}ms`);
    });
    
    // 修改输出资源
    compiler.hooks.emit.tapAsync('MyPlugin', (compilation, callback) => {
      // compilation.assets 包含所有待输出资源
      compilation.assets['README.md'] = {
        source: () => '# 构建信息\n' + JSON.stringify(compilation.getStats()),
        size: () => 1024
      };
      callback();
    });
    
    // 使用 Tapable 的流水线
    compiler.hooks.compilation.tap('MyPlugin', (compilation) => {
      compilation.hooks.optimizeModules.tap('MyPlugin', (modules) => {
        // 优化模块逻辑
      });
    });
  }
}
```

**常用钩子**：
- `entryOption`：处理入口配置后
- `afterPlugins`：插件初始化后
- `compile`：创建 compilation 前
- `emit`：输出资源到 output 目录前
- `done`：编译完成

### Vite 预构建原理

**核心机制**：依赖预构建（Pre-bundling）

```javascript
// 预构建流程
1. 扫描入口文件，识别所有第三方依赖（如 react, lodash）
2. 使用 esbuild 将所有依赖打包成单个文件
   - 将 CommonJS 转为 ESM
   - 合并模块，减少 HTTP 请求数
3. 生成到 node_modules/.vite/deps 目录
4. 重写模块导入路径，指向预构建文件

// 示例转换
// 原始代码
import React from 'react';

// 预构建后变为
import React from '/node_modules/.vite/deps/react.js?v=123456';
```

**为什么能加速**：
1. **减少请求**：将多个模块合并，浏览器请求数从 N 减少到 1
2. **ESM 格式**：现代浏览器原生支持，无需打包
3. **缓存策略**：依赖稳定，一次预构建长期复用
4. **按需编译**：只编译依赖，不处理业务代码（业务代码浏览器直接请求）

## 问题8延伸：实际项目安全漏洞案例及修复

### 案例1：XSS 漏洞修复

**场景**：富文本编辑器展示用户评论，未做过滤导致存储型 XSS

**漏洞发现**：安全扫描工具检测到用户输入 `<img src=x onerror=alert(1)>` 被执行

**修复方案**：
```javascript
// 1. 前端：使用 DOMPurify 净化
import DOMPurify from 'dompurify';

const SafeHTML = ({ html }) => {
  const cleanHtml = DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a', 'p', 'br'],
    ALLOWED_ATTR: ['href', 'target']
  });
  return <div dangerouslySetInnerHTML={{ __html: cleanHtml }} />;
};

// 2. 后端：增加双重过滤（CSP + 输出转义）
app.use((req, res, next) => {
  res.setHeader('Content-Security-Policy', 
    "default-src 'self'; script-src 'self' https://trusted.cdn.com;");
  next();
});
```

### 案例2：CSRF 漏洞修复

**场景**：用户修改邮箱接口未做 CSRF 防护，攻击者构造恶意页面诱导用户点击

**漏洞复现**：
```html
<!-- 攻击者网站 -->
<img src="https://example.com/api/change-email?email=hacker@evil.com" style="display:none">
```

**修复方案**：
```javascript
// 1. 后端生成 CSRF Token
app.use(csrf({ cookie: true }));

// 2. 前端请求携带 Token
axios.interceptors.request.use(config => {
  const token = document.querySelector('meta[name="csrf-token"]').content;
  config.headers['X-CSRF-Token'] = token;
  return config;
});

// 3. Cookie 设置 SameSite
res.cookie('session', token, {
  httpOnly: true,
  sameSite: 'strict',  // 关键：禁止第三方请求携带
  secure: true
});
```

### 推动修复的流程

1. **发现阶段**：安全团队扫描报告 → 建立漏洞清单（P0-P3 分级）
2. **评估影响**：分析漏洞利用可能性、受影响用户范围
3. **修复验证**：
   - 本地修复后使用 OWASP ZAP 扫描
   - 部署预发布环境验证绕过方案
4. **灰度发布**：5% → 50% → 100%，监控错误率
5. **复盘总结**：建立安全编码规范，纳入 Code Review 清单

## 问题9延伸：架构设计复盘 - 改进空间

### 原架构设计回顾

假设项目采用了 **qiankun 微前端** 方案，以下是可改进的点：

**改进1：模块联邦替代 qiankun**
```javascript
// 原方案：qiankun 需要主应用配置和子应用改造
registerMicroApps([
  { name: 'app1', entry: '//localhost:3001', container: '#container' }
]);

// 改进方案：Webpack Module Federation
// 主应用配置
new ModuleFederationPlugin({
  name: 'host',
  remotes: {
    app1: 'app1@http://localhost:3001/remoteEntry.js'
  }
});

// 子应用暴露组件
new ModuleFederationPlugin({
  name: 'app1',
  exposes: {
    './routes': './src/routes'
  }
});
```

**优势**：
- 无需改造子应用生命周期
- 真正的运行时模块共享，避免重复加载依赖
- 更好的 TypeScript 支持

**改进2：状态管理优化**
- 原方案：Redux 全局 store，导致微应用间状态耦合
- 改进：每个微应用独立 store，通过 CustomEvent 通信
```javascript
// 跨应用通信
window.dispatchEvent(new CustomEvent('app-login', { 
  detail: { userInfo } 
}));

// 接收方
window.addEventListener('app-login', (e) => {
  // 处理登录事件
});
```

**改进3：构建部署优化**
- 原方案：每个微应用独立构建，缺少依赖共享
- 改进：提取公共依赖为 CDN，子应用按需加载
```yaml
# 依赖管理策略
公共依赖:
  - react@18
  - react-dom@18
  - antd@5
  - dayjs
  
CDN策略: 生产环境使用 unpkg，开发环境使用本地预构建
```

### 当时妥协的原因
1. **时间压力**：项目周期仅3个月，qiankun 生态成熟，接入快
2. **团队熟悉度**：团队对 Webpack 5 Module Federation 不熟悉
3. **旧系统兼容**：部分子应用是 jQuery 老项目，qiankun 的 JS 沙箱更稳定

### 新架构价值
- 构建时间从 8 分钟降至 2 分钟（模块复用）
- 公共依赖体积减少 40%
- 子应用独立发布，互不影响

## 问题10延伸：如何评估新技术是否引入团队

### 评估框架：TAM 模型（技术、业务、团队）

**1. 技术维度（40%）**
```
- 成熟度：版本号、社区活跃度、issue 响应速度
- 生态：文档完善度、第三方插件、学习资源
- 性能：基准测试数据、与现有方案对比
- 维护性：作者维护记录、核心贡献者数量
```

**评估表示例**：
| 维度 | 指标 | 权重 | 评分(1-5) |
|------|------|------|-----------|
| 成熟度 | 生产环境验证 | 15% | 4 |
| 生态 | npm 周下载量 | 10% | 5 |
| 性能 | 构建速度提升 | 10% | 4 |
| 学习曲线 | 文档质量 | 5% | 3 |

**2. 业务维度（35%）**
```
- 解决问题：是否解决当前痛点？（如构建慢、维护难）
- ROI：投入产出比（迁移成本 vs 长期收益）
- 风险：引入失败的回退方案
- 长期价值：技术路线是否匹配公司3年规划
```

**3. 团队维度（25%）**
```
- 学习意愿：团队成员主动学习积极性
- 技能匹配：现有技术栈过渡难度
- 试点可行性：能否先在小项目验证
- 知识传承：是否有技术骨干能主导
```

### 实践流程

**第1-2周：调研与验证**
```markdown
1. 技术选型文档（对比3个以上方案）
2. POC 原型（核心功能实现）
3. 性能基准测试报告
4. 风险评估与回滚方案
```

**第3周：团队共识**
- 技术分享会：演示 POC，讲解优劣
- 投票或共识机制（核心成员一致同意）
- 建立“技术雷达”，明确采纳、试点、观望、淘汰分类

**第4周后：渐进式引入**
```javascript
// 策略：优先级排序
const adoptionStrategy = {
  phase1: '非核心模块试点（1个月）',
  phase2: '收集反馈、优化坑点（2个月）',

};
```
