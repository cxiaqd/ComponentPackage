## 一、首屏加载慢（白屏时间长）

### 问题场景
页面打开后长时间白屏，用户看到空白页面数秒后才出现内容。

### 原因分析
- 关键资源（CSS、JS）体积过大，阻塞渲染
- 未做代码分割，所有代码一起加载
- 首屏所需数据接口响应慢
- 未使用骨架屏或占位符

### 解决方案

#### 1. 关键 CSS 内联 + 非关键 CSS 异步加载
```html
<!-- 内联首屏关键样式 -->
<style>
  .hero { background: #007bff; height: 100vh; }
  .nav { display: flex; }
</style>

<!-- 非关键 CSS 异步加载 -->
<link rel="preload" href="non-critical.css" as="style" onload="this.onload=null;this.rel='stylesheet'">
<noscript><link rel="stylesheet" href="non-critical.css"></noscript>
```

#### 2. 代码分割与路由懒加载（以 Vue 为例）
```javascript
// router.js
const Home = () => import(/* webpackChunkName: "home" */ './views/Home.vue')
const About = () => import(/* webpackChunkName: "about" */ './views/About.vue')
```

#### 3. 骨架屏（Skeleton Screen）
```vue
<template>
  <div v-if="loading" class="skeleton">
    <div class="skeleton-avatar"></div>
    <div class="skeleton-line"></div>
  </div>
  <div v-else>
    <!-- 实际内容 -->
  </div>
</template>

<style>
.skeleton {
  background: #f0f0f0;
  animation: pulse 1.5s infinite;
}
@keyframes pulse {
  0% { opacity: 0.6; }
  50% { opacity: 1; }
  100% { opacity: 0.6; }
}
</style>
```

#### 4. 预加载关键资源
```html
<link rel="preload" href="hero-image.jpg" as="image">
<link rel="preload" href="critical-font.woff2" as="font" crossorigin>
```

## 二、图片体积过大导致加载慢

### 问题场景
图片资源过大，特别是在移动端，加载时间长、流量消耗大。

### 解决方案

#### 1. 使用现代图片格式（WebP、AVIF）
```html
<picture>
  <source srcset="image.avif" type="image/avif">
  <source srcset="image.webp" type="image/webp">
  <img src="image.jpg" alt="fallback">
</picture>
```

#### 2. 响应式图片（根据屏幕宽度加载不同尺寸）
```html
<img src="small.jpg"
     srcset="small.jpg 480w, medium.jpg 800w, large.jpg 1200w"
     sizes="(max-width: 600px) 480px, (max-width: 1000px) 800px, 1200px"
     alt="responsive">
```

#### 3. 图片懒加载（Intersection Observer）
```javascript
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      const img = entry.target;
      img.src = img.dataset.src;
      observer.unobserve(img);
    }
  });
});

document.querySelectorAll('img[data-src]').forEach(img => observer.observe(img));
```

#### 4. 使用原生懒加载属性
```html
<img loading="lazy" src="image.jpg" alt="lazy">
```

## 三、打包体积过大

### 问题场景
Webpack 打包后的文件体积大，导致加载时间长。

### 解决方案

#### 1. 代码分割（SplitChunks）
```javascript
// webpack.config.js
optimization: {
  splitChunks: {
    chunks: 'all',
    cacheGroups: {
      vendor: {
        test: /[\\/]node_modules[\\/]/,
        name: 'vendors',
        chunks: 'all',
      },
      common: {
        minChunks: 2,
        name: 'common',
      }
    }
  }
}
```

#### 2. Tree Shaking 配置
```javascript
// webpack.config.js
mode: 'production',
optimization: {
  usedExports: true,
}
```

```json
// package.json
{
  "sideEffects": false,  // 无副作用
  // 或指定有副作用的文件
  "sideEffects": ["*.css", "*.scss"]
}
```

#### 3. 动态导入（按需加载）
```javascript
// 按需加载模块
const module = await import('./heavy-module.js');
module.doSomething();
```

#### 4. 使用 Bundle Analyzer 分析体积
```bash
npm install --save-dev webpack-bundle-analyzer
```

```javascript
// webpack.config.js
const BundleAnalyzerPlugin = require('webpack-bundle-analyzer').BundleAnalyzerPlugin;
plugins: [new BundleAnalyzerPlugin()]
```

## 四、运行时卡顿（掉帧、滚动不流畅）

### 问题场景
页面滚动或动画时出现卡顿，帧率低。

### 原因分析
- 强制同步布局（读写交错）
- 动画触发布局（动画非 transform/opacity）
- 主线程被长任务阻塞

### 解决方案

#### 1. 使用 transform 代替 top/left
```css
/* ❌ 不好 */
.animate {
  transition: left 0.3s;
  left: 0;
}
.animate:hover {
  left: 100px; /* 触发重排 */
}

/* ✅ 好 */
.animate {
  transition: transform 0.3s;
  transform: translateX(0);
}
.animate:hover {
  transform: translateX(100px); /* 只触发合成 */
}
```

#### 2. 使用 will-change 提前创建合成层
```css
.animated {
  will-change: transform, opacity;
}
```

#### 3. 避免强制同步布局
```javascript
// ❌ 错误
const width = element.offsetWidth;
element.style.width = width + 10 + 'px';

// ✅ 正确
const width = element.offsetWidth;
// 批量读取后统一写入
requestAnimationFrame(() => {
  element.style.width = width + 10 + 'px';
});
```

#### 4. 长任务拆分（使用 setTimeout 或 requestIdleCallback）
```javascript
async function processLargeArray(arr) {
  const chunkSize = 1000;
  let index = 0;
  while (index < arr.length) {
    const chunk = arr.slice(index, index + chunkSize);
    processChunk(chunk);
    index += chunkSize;
    // 让出主线程
    await new Promise(resolve => setTimeout(resolve, 0));
  }
}
```

#### 5. 滚动事件节流 + requestAnimationFrame
```javascript
let ticking = false;
window.addEventListener('scroll', () => {
  if (!ticking) {
    requestAnimationFrame(() => {
      // 执行滚动处理逻辑
      updateUI();
      ticking = false;
    });
    ticking = true;
  }
});
```

## 五、内存泄漏

### 问题场景
页面长时间运行后内存占用持续增长，最终变卡或崩溃。

### 常见原因及修复

#### 1. 未清理的定时器
```javascript
export default {
  data() {
    return { timer: null };
  },
  mounted() {
    this.timer = setInterval(() => {
      // do something
    }, 1000);
  },
  beforeDestroy() {
    clearInterval(this.timer); // 必须清理
  }
}
```

#### 2. 未移除的事件监听
```javascript
export default {
  mounted() {
    window.addEventListener('resize', this.handleResize);
  },
  beforeDestroy() {
    window.removeEventListener('resize', this.handleResize);
  }
}
```

#### 3. 闭包引用大对象
```javascript
function createHeavyClosure() {
  const largeData = new Array(1000000).fill('data');
  return function() {
    // 虽然不用 largeData，但闭包持有引用
    console.log('hello');
  };
}
// 解决方案：手动释放
function createLightClosure() {
  const largeData = new Array(1000000).fill('data');
  const fn = () => console.log('hello');
  largeData = null; // 主动释放
  return fn;
}
```

#### 4. DOM 引用未清除
```javascript
// 将 DOM 引用保存在数组或对象中
let elements = [];
elements.push(document.getElementById('btn'));
// 移除 DOM 时，同时从数组中删除
function removeElement() {
  const el = document.getElementById('btn');
  el.remove();
  elements = elements.filter(e => e !== el);
}
```

#### 5. 使用 WeakMap/WeakSet 避免强引用
```javascript
const cache = new WeakMap(); // 键为对象，对象被回收时条目自动删除
function cacheData(obj, data) {
  cache.set(obj, data);
}
```

## 六、网络请求过多/重复请求

### 问题场景
页面发起大量重复请求，或同一资源多次请求，影响性能。

### 解决方案

#### 1. 请求去重（同一时间多个相同请求只发一次）
```javascript
class RequestDeduplicator {
  constructor() {
    this.pending = new Map();
  }
  
  async request(config) {
    const key = JSON.stringify(config);
    if (this.pending.has(key)) {
      return this.pending.get(key);
    }
    const promise = axios(config).finally(() => {
      this.pending.delete(key);
    });
    this.pending.set(key, promise);
    return promise;
  }
}
```

#### 2. 请求缓存（时效性数据）
```javascript
const cache = new Map();
async function fetchWithCache(url, ttl = 60000) {
  const cached = cache.get(url);
  if (cached && Date.now() < cached.expires) {
    return cached.data;
  }
  const data = await fetch(url).then(res => res.json());
  cache.set(url, { data, expires: Date.now() + ttl });
  return data;
}
```

#### 3. 请求合并（批量接口）
```javascript
let batchQueue = [];
let batchTimer = null;

function batchRequest(item) {
  batchQueue.push(item);
  if (!batchTimer) {
    batchTimer = setTimeout(async () => {
      const items = batchQueue.slice();
      batchQueue = [];
      batchTimer = null;
      const ids = items.map(i => i.id);
      const response = await axios.get(`/api/batch?ids=${ids.join(',')}`);
      // 根据 ids 分发给各个 promise
      items.forEach((item, idx) => {
        item.resolve(response.data[idx]);
      });
    }, 50);
  }
  return new Promise((resolve) => {
    batchQueue.push({ ...item, resolve });
  });
}
```

#### 4. 使用 HTTP/2 多路复用
无需额外代码，只需确保服务器支持 HTTP/2，可减少连接数，提升并发效率。

## 七、资源加载优化（预加载、预连接）

### 问题场景
关键资源加载晚，影响首屏；第三方资源阻塞。

### 解决方案

#### 1. DNS 预解析
```html
<link rel="dns-prefetch" href="https://api.example.com">
```

#### 2. 预连接（DNS + TCP + TLS）
```html
<link rel="preconnect" href="https://api.example.com" crossorigin>
```

#### 3. 预加载关键资源
```html
<link rel="preload" href="critical.js" as="script">
<link rel="preload" href="hero.png" as="image">
```

#### 4. 预获取下一页资源
```html
<link rel="prefetch" href="next-page.html">
```

#### 5. 预渲染（慎用，耗资源）
```html
<link rel="prerender" href="next-page.html">
```

## 八、移动端滚动性能问题

### 问题场景
移动端列表滚动卡顿，惯性滚动不流畅。

### 解决方案

#### 1. 使用 `-webkit-overflow-scrolling: touch`
```css
.scroll-container {
  overflow-y: auto;
  -webkit-overflow-scrolling: touch; /* 启用惯性滚动 */
}
```

#### 2. 虚拟滚动（只渲染可视区域）
```javascript
// 使用 react-window、vue-virtual-scroller 等库
import { FixedSizeList } from 'react-window';

const Row = ({ index, style }) => (
  <div style={style}>Row {index}</div>
);

const List = () => (
  <FixedSizeList
    height={400}
    itemCount={10000}
    itemSize={35}
    width={300}
  >
    {Row}
  </FixedSizeList>
);
```

#### 3. 避免在滚动事件中做复杂操作
使用 `requestAnimationFrame` + 节流，或改用 Intersection Observer。

## 九、字体加载导致文字闪烁（FOUT/FOIT）

### 问题场景
自定义字体加载前后出现无样式文本或不可见文本。

### 解决方案

#### 1. 使用 `font-display` 属性
```css
@font-face {
  font-family: 'MyFont';
  src: url('myfont.woff2') format('woff2');
  font-display: swap; /* 或 fallback, optional */
}
```

#### 2. 预加载字体文件
```html
<link rel="preload" href="myfont.woff2" as="font" type="font/woff2" crossorigin>
```

#### 3. 使用字体加载 API
```javascript
if ('fonts' in document) {
  document.fonts.load('1em MyFont').then(() => {
    document.body.classList.add('font-loaded');
  });
}
```

## 十、JavaScript 执行时间过长（长任务）

### 问题场景
主线程长时间被占用，用户交互无响应。

### 解决方案

#### 1. 拆分任务（setTimeout/queueMicrotask）
```javascript
function processLargeData(data) {
  const chunkSize = 500;
  let i = 0;
  function processChunk() {
    const end = Math.min(i + chunkSize, data.length);
    for (; i < end; i++) {
      // 处理单个数据
    }
    if (i < data.length) {
      setTimeout(processChunk, 0);
    }
  }
  processChunk();
}
```

#### 2. Web Worker 处理计算密集型任务
```javascript
// main.js
const worker = new Worker('worker.js');
worker.postMessage(largeData);
worker.onmessage = (e) => {
  console.log('计算结果', e.data);
};

// worker.js
self.onmessage = (e) => {
  const result = e.data.reduce((acc, val) => acc + val, 0);
  self.postMessage(result);
};
```

#### 3. 使用 `requestIdleCallback` 执行非紧急任务
```javascript
requestIdleCallback(() => {
  sendAnalytics();
  preloadNextPage();
}, { timeout: 2000 });
```
