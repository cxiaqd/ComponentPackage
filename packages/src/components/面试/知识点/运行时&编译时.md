**编译时（Compile Time）** 和 **运行时（Runtime）** 是程序生命周期的两个阶段，分别对应**代码被翻译成可执行形式**的阶段和**代码实际执行**的阶段。

---

## 1. 编译时（Compile Time）

编译时是指**源代码被编译器（或解释器）处理，转换为目标代码（如机器码、字节码）或进行语法分析、类型检查等工作的阶段**。

**主要活动：**
- 语法分析（检查语法错误）
- 词法分析（将代码分解为词法单元）
- 语义分析（类型检查、变量/函数声明等）
- 优化（如内联、死代码消除）
- 生成中间代码或目标代码

**特点：**
- 发生在程序运行**之前**。
- 错误（如语法错误、类型不匹配）在编译时就能发现，程序无法运行直到修复。
- 变量地址、函数地址等静态信息可能被确定。

**示例（C/C++）：**
```c
int a = 10;
int b = a + 20;   // 编译器在编译时计算 a+20? 不，a 是变量，需要运行时计算
const int c = 30; // 编译时常量，可能被编译器直接替换
```
在 C/C++ 中，`const int c = 30;` 在编译时就确定了值，可以直接嵌入代码。

**在 JavaScript 中：**
JavaScript 是解释型/即时编译（JIT）语言，但依然有“编译时”概念：
- 引擎首先解析代码，进行词法/语法分析，生成抽象语法树（AST）。
- 检测语法错误（如 `if ( ) {` 缺少括号）会在**解析阶段**报错，程序不运行。
- 变量提升、作用域链等也在编译时确定（虽然执行时才会赋值）。

例如：
```javascript
console.log(a); // undefined，变量提升在编译时已处理，但赋值在运行时
var a = 5;
```
`var a` 的声明被提升到作用域顶端，这是在编译时完成的。

---

## 2. 运行时（Runtime）

运行时是指**程序在计算机上实际执行、指令被 CPU 执行、内存被分配、函数被调用等阶段**。

**主要活动：**
- 执行指令
- 分配内存（对象、数组等）
- 函数调用、参数传递
- 动态类型计算（在动态语言中）
- 异常抛出与处理

**特点：**
- 发生在程序运行期间。
- 错误（如 `undefined` 的访问、类型错误）在运行时才会出现。
- 动态特性（如通过变量访问属性、`eval`）只能在运行时确定。

**示例：**
```javascript
function add(a, b) {
  return a + b;
}
add(1, 2); // 运行时才执行加法
```
编译时只知道 `add` 是一个函数，但不知道参数的具体值，加法操作在运行时进行。

---

## 3. 对比表

| 维度 | 编译时 | 运行时 |
|------|--------|--------|
| **发生时间** | 代码执行之前 | 代码执行期间 |
| **主要任务** | 语法分析、类型检查、生成代码 | 指令执行、内存分配、动态操作 |
| **错误类型** | 语法错误、类型错误（静态语言） | 逻辑错误、空指针、动态类型错误 |
| **变量值** | 常量值可能确定，变量值未知 | 变量值被计算、传递 |
| **性能影响** | 编译优化可以提升运行效率 | 运行时的性能开销取决于算法、I/O 等 |

---

## 4. 在 JavaScript 中的具体体现

### 编译时（解析阶段）
- 检查语法错误：`function foo( { }` → 直接报错，代码不运行。
- 变量提升：`var a;` 在编译时被识别，但 `a` 的值直到运行时才被赋值。
- 作用域确定：函数作用域、块作用域在编译时已建立。

### 运行时
- 函数调用：实际执行函数体，传递参数。
- 动态属性访问：`obj[property]` 中的 `property` 在运行时求值。
- 原型链查找：当访问对象属性时，在运行时沿原型链搜索。
- `this` 绑定：取决于调用方式，在运行时确定。

---

## 5. 与之前代码示例的关联

之前我们讨论的柯里化、偏函数代码，其大部分行为发生在**运行时**：
- 函数被调用时，参数传递、`apply` 方法调用、闭包捕获变量等都是在运行时完成的。
- 但函数声明、变量定义（如 `const infoLog = partial(...)`）中的变量提升、作用域规则是在编译时确定的。

了解编译时和运行时的区别，有助于理解 JavaScript 引擎的工作方式，以及为什么有些错误在运行前就能发现，而有些必须在运行时才能捕获。
