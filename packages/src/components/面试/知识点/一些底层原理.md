## 一、虚拟DOM Diff算法

### 问题1：Vue 2的Diff算法是如何实现的？Vue 3做了哪些优化？实际开发中如何避免Diff性能问题？

**考察点**：对Vue渲染机制的理解，以及性能优化的实践经验

**参考答案**：

---

#### Vue 2 的 Diff 算法实现

**核心策略**：**同层比较 + 双端对比**

Vue 2 的 Diff 过程发生在 `patch` 函数中，当新旧虚拟DOM节点相同时，会调用 `patchVnode` 进行子节点对比。

**双端对比算法流程**：

```javascript
// 简化版 Vue 2 双端对比
function updateChildren(parentElm, oldCh, newCh) {
  let oldStartIdx = 0;              // 旧子节点起始索引
  let oldEndIdx = oldCh.length - 1; // 旧子节点结束索引
  let newStartIdx = 0;              // 新子节点起始索引
  let newEndIdx = newCh.length - 1; // 新子节点结束索引
  
  let oldStartVnode = oldCh[0];
  let oldEndVnode = oldCh[oldEndIdx];
  let newStartVnode = newCh[0];
  let newEndVnode = newCh[newEndIdx];
  
  while (oldStartIdx <= oldEndIdx && newStartIdx <= newEndIdx) {
    // 1. 旧头 vs 新头
    if (sameVnode(oldStartVnode, newStartVnode)) {
      patchVnode(oldStartVnode, newStartVnode);
      oldStartVnode = oldCh[++oldStartIdx];
      newStartVnode = newCh[++newStartIdx];
    }
    // 2. 旧尾 vs 新尾
    else if (sameVnode(oldEndVnode, newEndVnode)) {
      patchVnode(oldEndVnode, newEndVnode);
      oldEndVnode = oldCh[--oldEndIdx];
      newEndVnode = newCh[--newEndIdx];
    }
    // 3. 旧头 vs 新尾（节点移动到尾部）
    else if (sameVnode(oldStartVnode, newEndVnode)) {
      patchVnode(oldStartVnode, newEndVnode);
      // 将旧头节点移动到尾部
      parentElm.insertBefore(oldStartVnode.elm, oldEndVnode.elm.nextSibling);
      oldStartVnode = oldCh[++oldStartIdx];
      newEndVnode = newCh[--newEndIdx];
    }
    // 4. 旧尾 vs 新头（节点移动到头部）
    else if (sameVnode(oldEndVnode, newStartVnode)) {
      patchVnode(oldEndVnode, newStartVnode);
      parentElm.insertBefore(oldEndVnode.elm, oldStartVnode.elm);
      oldEndVnode = oldCh[--oldEndIdx];
      newStartVnode = newCh[++newStartIdx];
    }
    // 5. 找不到复用节点，使用 key 索引查找
    else {
      // 建立旧节点的 key 索引映射
      if (!keyIndexMap) {
        keyIndexMap = createKeyIndexMap(oldCh, oldStartIdx, oldEndIdx);
      }
      const idxInOld = keyIndexMap[newStartVnode.key];
      if (!idxInOld) {
        // 新节点，创建插入
        createElm(newStartVnode, parentElm, oldStartVnode.elm);
      } else {
        // 复用旧节点，移动位置
        const vnodeToMove = oldCh[idxInOld];
        patchVnode(vnodeToMove, newStartVnode);
        parentElm.insertBefore(vnodeToMove.elm, oldStartVnode.elm);
        oldCh[idxInOld] = undefined; // 标记已处理
      }
      newStartVnode = newCh[++newStartIdx];
    }
  }
  
  // 添加剩余新节点或删除多余旧节点
  if (oldStartIdx > oldEndIdx) {
    addVnodes(parentElm, newCh, newStartIdx, newEndIdx);
  } else if (newStartIdx > newEndIdx) {
    removeVnodes(parentElm, oldCh, oldStartIdx, oldEndIdx);
  }
}
```

**Vue 2 Diff 的特点**：
- **双端对比**：同时从头部和尾部开始比较，能高效处理节点反转、头尾移动等场景
- **复用判断**：通过 `sameVnode` 判断（`key` + `tag` + 是否为注释节点等）
- **缺点**：当列表没有 key 或使用 index 作为 key 时，在中间插入/删除节点会导致后续节点全部重新渲染

#### Vue 3 的 Diff 优化

Vue 3 引入了 **编译时优化** + **最长递增子序列算法**，大幅提升 Diff 性能。

**1. 编译时优化：Block Tree + PatchFlags**

Vue 3 在编译阶段会标记动态节点，运行时只 Diff 动态内容：

```html
<!-- 模板 -->
<div>
  <div>{{ name }}</div>
  <div class="static">静态内容</div>
  <div :class="dynamicClass">动态类名</div>
</div>
```

```javascript
// 编译后生成的渲染函数（简化）
function render() {
  return createBlock('div', null, [
    createVNode('div', null, toDisplayString(name), 1 /* TEXT */),
    createVNode('div', { class: 'static' }, '静态内容', -1 /* 静态节点 */),
    createVNode('div', { class: dynamicClass }, '动态类名', 2 /* CLASS */)
  ])
}
```

**PatchFlags 标识**：告诉运行时哪些属性是动态的，避免无意义的对比。

**2. 最长递增子序列优化**

Vue 3 在处理列表渲染时，通过**最长递增子序列（LIS）**算法找出最少需要移动的节点：

```javascript
// 简化版 Vue 3 列表 Diff
function getSequence(arr) {
  // 找到最长递增子序列的索引
  // 例如：arr = [2, 1, 3, 4, 5, 0]
  // 最长递增子序列索引 = [1, 2, 3, 4]（对应值 1, 3, 4, 5）
  // 只有不在序列中的节点才需要移动

```

**效果对比**：
| 场景 | Vue 2 操作 | Vue 3 操作 |
|------|-----------|-----------|
| 列表反转 | 移动所有节点 | 只需移动少量节点 |
| 中间插入 | 后续节点全部移动 | 仅插入新节点，其他不动 |

#### 实际开发中如何避免 Diff 性能问题

**1. 正确使用 key**

```vue
<!-- ❌ 错误：使用 index 作为 key -->
<li v-for="(item, index) in list" :key="index">{{ item.name }}</li>

<!-- ✅ 正确：使用唯一标识 -->
<li v-for="item in list" :key="item.id">{{ item.name }}</li>
```

**为什么 index 不行**？
- 当列表中间插入数据时，index 会变化，导致 Diff 算法认为所有节点都变了，全部重新渲染
- 组件状态（如输入框内容）会错乱

**2. 避免在模板中写复杂表达式**

```vue
<!-- ❌ 每次渲染都会重新计算 -->
<div>{{ expensiveCalculation(list) }}</div>

<!-- ✅ 使用计算属性缓存结果 -->
<div>{{ computedValue }}</div>
```

**3. 合理使用 v-show 和 v-if**

```vue
<!-- 频繁切换用 v-show（操作 CSS） -->
<div v-show="isVisible">频繁切换</div>

<!-- 很少变化用 v-if（操作 DOM） -->
<div v-if="isVisible">条件渲染</div>
```

**4. 列表项组件化 + 合理拆分**

```vue
<!-- 将复杂的列表项拆分为独立组件 -->
<ListItem
  v-for="item in list"
  :key="item.id"
  :data="item"
/>
```

配合 `v-once` 处理静态内容：
```vue
<div v-once>
  <!-- 大量静态内容，只在初始化时渲染一次 -->
</div>
```

### 问题2：在 Vue 中，为什么组件更新时子组件可能会被重新渲染？如何避免不必要的子组件更新？

**考察点**：对 Vue 响应式更新机制的理解，以及组件优化的实践经验

**参考答案**：

**原因分析**：

Vue 的组件更新遵循 **自上而下** 的流程：
1. 父组件数据变化 → 父组件的渲染函数重新执行
2. 渲染函数执行过程中，会重新创建虚拟DOM树
3. 子组件作为虚拟节点，会被重新对比（`patch`）
4. 即使子组件 props 未变化，如果虚拟节点被重新创建，也可能触发子组件更新

**避免策略**：

**1. 使用 `v-once` 处理静态内容**

```vue
<template>
  <div>
    <!-- 静态内容，只渲染一次 -->
    <div v-once>
      <h1>{{ title }}</h1>
      <p>这段内容不会变化</p>
    </div>
    <!-- 动态内容正常渲染 -->
    <div>{{ dynamicData }}</div>
  </div>
</template>
```

**2. 使用 `computed` 派生数据**

```vue
<script>
export default {
  data() {
    return {
      list: [/* 大量数据 */],
      filterText: ''
    }
  },
  computed: {
    // 只有当依赖变化时才重新计算
    filteredList() {
      return this.list.filter(item => item.includes(this.filterText))
    }
  }
}
</script>
```

**3. 合理使用 `v-memo`（Vue 3.2+）**

```vue
<!-- 缓存子树的渲染结果，依赖的数组未变化时跳过更新 -->
<div v-for="item in list" :key="item.id" v-memo="[item.id, item.selected]">
  <p>{{ item.name }}</p>
  <p>{{ item.desc }}</p>
</div>
```

**4. 组件层面优化**

```vue
<script>
// 使用函数式组件（Vue 2），减少实例开销
export default {
  functional: true,
  render(h, context) {
    // 没有响应式数据，只依赖 props
  }
}

// Vue 3 使用 defineProps 配合 shallowRef
import { shallowRef } from 'vue'

export default {
  setup() {
    const largeData = shallowRef({ /* 大量数据 */ })
    // shallowRef 只监听 .value 的变化，不深度监听
  }
}
</script>
```

**5. 使用 `shouldUpdate` 或手动控制**

Vue 2 中可以使用 `$forceUpdate` 控制，但一般不推荐。更好的方式是拆分组件，让变化范围最小化。

## 二、响应式原理（Proxy / defineProperty）

### 问题3：Vue 2 和 Vue 3 响应式原理的核心区别是什么？Vue 2 响应式有哪些缺陷？Vue 3 是如何解决的？

**考察点**：对响应式系统底层的理解，以及 Vue 3 改进方向的认知

**参考答案**：

---

#### Vue 2：Object.defineProperty

**核心实现**：

```javascript
// 简化版 Vue 2 响应式实现
function defineReactive(obj, key, val) {
  // 递归处理嵌套对象
  observe(val);
  
  const dep = new Dep(); // 依赖收集器
  
  Object.defineProperty(obj, key, {
    get() {
      if (Dep.target) {
        dep.depend(); // 收集依赖
      }
      return val;
    },
    set(newVal) {
      if (val === newVal) return;
      val = newVal;
      observe(newVal); // 新值也需要响应式
      dep.notify(); // 通知更新
    }
  });
}
```

**Vue 2 响应式的缺陷**：

1. **对象属性增删无法检测**
   ```javascript
   data() {
     return { user: { name: 'John' } }
   }
   
   // ❌ 无法触发更新
   this.user.age = 18;
   // ✅ 需要使用 Vue.set
   this.$set(this.user, 'age', 18);
   
   // ❌ 无法触发更新
   delete this.user.name;
   // ✅ 需要使用 Vue.delete
   this.$delete(this.user, 'name');
   ```

2. **数组索引和 length 修改无法检测**
   ```javascript
   data() {
     return { list: ['a', 'b', 'c'] }
   }
   
   // ❌ 无法触发更新
   this.list[0] = 'x';
   // ✅ 需要使用 splice 或 Vue.set
   this.list.splice(0, 1, 'x');
   
   // ❌ 无法触发更新
   this.list.length = 0;
   // ✅ 需要使用 splice
   this.list.splice(0);
   ```

3. **初始化时递归遍历所有属性**，即使属性从未被使用，也会创建响应式
   ```javascript
   data() {
     return {
       // 即使 deepData 从未被使用，也会深度遍历
       deepData: { /* 嵌套很深的对象 */ }
     }
   }
   ```

4. **不支持 Map、Set 等新数据结构**

---

#### Vue 3：Proxy

**核心实现**：

```javascript
// 简化版 Vue 3 响应式实现
function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      // 依赖收集
      track(target, key);
      
      const res = Reflect.get(target, key, receiver);
      // 懒代理：只有访问时才递归转换
      if (isObject(res)) {
        return reactive(res);
      }
      return res;
    },
    
    set(target, key, value, receiver) {
      const oldValue = target[key];
      const result = Reflect.set(target, key, value, receiver);
      
      if (oldValue !== value) {
        // 触发更新
        trigger(target, key);
      }
      return result;
    },
    
    deleteProperty(target, key) {
      const hadKey = hasOwn(target, key);
      const result = Reflect.deleteProperty(target, key);
      
      if (hadKey && result) {
        trigger(target, key);
      }
      return result;
    }
  });
}
```

**Vue 3 响应式的优势**：

1. **自动检测属性增删**
   ```javascript
   const state = reactive({ user: { name: 'John' } });
   
   // ✅ 自动触发更新
   state.user.age = 18;
   // ✅ 自动触发更新
   delete state.user.name;
   ```

2. **数组索引和 length 完美支持**
   ```javascript
   const list = reactive(['a', 'b', 'c']);
   
   // ✅ 自动触发更新
   list[0] = 'x';
   // ✅ 自动触发更新
   list.length = 0;
   ```

3. **懒代理（Lazy Proxy）**
   ```javascript
   const state = reactive({
     deep: { /* 深层嵌套对象 */ }
   });
   
   // 只有访问 state.deep 时，才递归创建 Proxy
   // 初始化性能更好
   ```

4. **支持 Map、Set、WeakMap 等**
   ```javascript
   const map = reactive(new Map());
   map.set('key', 'value'); // ✅ 自动触发更新
   ```

---

#### 实际开发中的注意事项

**Vue 2 常见坑**：
```javascript
// 场景1：动态添加对象属性
// ❌ 错误做法
this.user.newProp = 'value';
// ✅ 正确做法
this.$set(this.user, 'newProp', 'value');

// 场景2：修改数组项
// ❌ 错误做法
this.list[2] = newValue;
// ✅ 正确做法
this.$set(this.list, 2, newValue);
// 或
this.list.splice(2, 1, newValue);
```

**Vue 3 注意事项**：
```javascript
// 1. 解构会丢失响应性
const { name } = reactive({ name: 'John', age: 18 });
// name 不再是响应式的

// 解决方案：使用 toRefs
const { name, age } = toRefs(state);

// 2. 避免直接赋值整个响应式对象
let state = reactive({ count: 0 });
// ❌ 错误：会断开响应式连接

// ✅ 正确：修改属性
```

### 问题4：Vue 的依赖收集是如何实现的？在什么情况下会出现依赖收集遗漏？

**考察点**：对响应式系统实现细节的理解，以及实际开发中的坑点

**参考答案**：

---

#### 依赖收集机制

**核心三要素**：
- **Dep**：依赖管理器，每个响应式属性都有一个 Dep
- **Watcher**：观察者，负责执行更新函数
- **target**：当前正在执行的 Watcher

**收集流程**：

```javascript
// 简化版依赖收集流程
class Dep {
  constructor() {
    this.subs = new Set(); // 存储 Watcher
  }
  
  depend() {
    if (Dep.target) {
      this.subs.add(Dep.target);
    }
  }
  
  notify() {
    this.subs.forEach(watcher => watcher.update());
  }
}

class Watcher {
  constructor(getter, callback) {
    this.getter = getter;
    this.callback = callback;
    this.value = this.get();
  }
  
  get() {
    Dep.target = this;           // 设置当前 Watcher
    const value = this.getter(); // 执行 getter，触发依赖收集
    Dep.target = null;           // 清除
    return value;
  }
  
  update() {
    const newValue = this.get();
    this.callback(newValue, this.value);
    this.value = newValue;
  }
}

// 使用示例
new Watcher(() => {
  // 这个函数中访问的所有响应式属性都会被收集依赖
  return this.count + this.name;
}, (newVal, oldVal) => {
  console.log(`值从 ${oldVal} 变为 ${newVal}`);
});
```

---

#### 依赖收集遗漏的场景

**1. 对象属性新增/删除（Vue 2）**
```javascript
// Vue 2 中
data() {
  return { user: { name: 'John' } }
}

// ❌ 新增属性不会自动收集依赖
this.user.age = 18;  // 没有对应的 Dep，无法触发更新

// 解决方案：使用 $set
this.$set(this.user, 'age', 18);
```

**2. 数组索引修改（Vue 2）**
```javascript
// ❌ 不会触发依赖
this.list[0] = newValue;

// 原理：数组索引的 getter/setter 没有被定义
// 解决方案：使用 splice 或 $set
this.list.splice(0, 1, newValue);
```

**3. 条件分支导致的依赖收集遗漏**
```javascript
computed: {
  displayValue() {
    // 假设 showName 初始为 true
    if (this.showName) {
      // 只有 name 被收集了依赖
      return this.name;
    } else {
      // 当 showName 变为 false 时，age 没有被收集过依赖
      return this.age;
    }
  }
}
```

**问题**：当 `showName` 从 `true` 变为 `false` 时，`age` 从未被访问过，因此没有收集依赖，后续 `age` 变化不会触发更新。

**解决方案**：确保所有可能用到的响应式数据都被访问到
```javascript
computed: {
  displayValue() {
    // 强制访问所有可能用到的属性
    const { name, age, showName } = this;
    return showName ? name : age;
  }
}
```

**4. 闭包中的变量**
```javascript
data() {
  return {
    count: 0
  }
},
mounted() {
  // ❌ setTimeout 中访问的 count 没有建立依赖关系
  setTimeout(() => {
    console.log(this.count); // 只是读取，但没有 Watcher 在收集
  }, 1000);
  
  // 正确的依赖收集应该在渲染函数或计算属性中
}
```

**5. 使用索引访问数组元素后再修改**
```javascript
// Vue 3 中，以下场景可能产生问题
const state = reactive({
  items: [
    { id: 1, value: 'a' },
    { id: 2, value: 'b' }
  ]
});

// 先获取某个元素的引用
const item = state.items[0];

// 后续修改引用对象的属性
item.value = 'c'; // ✅ 可以触发更新

// 但如果直接替换整个数组元素
state.items[0] = { id: 1, value: 'c' }; // ✅ 也可以触发
```

## 三、Event Loop（事件循环）

### 问题5：Vue 中为什么对同一个响应式数据的多次修改只会触发一次视图更新？$nextTick 的实现原理是什么？

**考察点**：对 Vue 异步更新队列的理解，以及 Event Loop 的实际应用

**参考答案**：

---

#### Vue 的异步更新机制

**核心原理**：
Vue 将数据变化后的视图更新操作放入**异步队列**，多次数据修改只生成一个更新任务。

```javascript
// 简化版 Vue 异步更新实现
class Scheduler {
  constructor() {
    this.queue = [];      // 存储需要更新的 Watcher
    this.has = {};        // 去重
    this.waiting = false; // 是否正在等待执行
  }
  
  addWatcher(watcher) {
    const id = watcher.id;
    if (!this.has[id]) {
      this.has[id] = true;
      this.queue.push(watcher);
      
      if (!this.waiting) {
        this.waiting = true;
        // 使用微任务或宏任务执行更新
        nextTick(this.flush.bind(this));
      }
    }
  }
  
  flush() {
    // 对 Watcher 排序，确保父组件先于子组件更新
    this.queue.sort((a, b) => a.id - b.id);
    
    for (let i = 0; i < this.queue.length; i++) {
      this.queue[i].run();
    }
    
    // 重置状态
    this.queue.length = 0;
    this.has = {};
    this.waiting = false;
  }
}
```

**执行流程**：
```
用户修改数据 → 触发 setter → 通知 Watcher → Watcher 加入队列 → 
nextTick 调度 → 微任务队列 → 清空队列，执行更新 → 视图渲染
```

---

#### $nextTick 的实现原理

**Vue 2 实现**（优先使用微任务，降级使用宏任务）：

```javascript
// Vue 2.6+ 的 nextTick 实现
let timerFunc;

// 优先使用 Promise（微任务）
if (typeof Promise !== 'undefined') {
  timerFunc = () => {
    Promise.resolve().then(flushCallbacks);
  };
}
// 降级使用 MutationObserver（微任务）
else if (typeof MutationObserver !== 'undefined') {
  let counter = 1;
  const observer = new MutationObserver(flushCallbacks);
  const textNode = document.createTextNode(String(counter));
  observer.observe(textNode, { characterData: true });
  timerFunc = () => {
    counter = (counter + 1) % 2;
    textNode.data = String(counter);
  };
}
// 降级使用 setImmediate（宏任务，仅 IE 支持）
else if (typeof setImmediate !== 'undefined') {
  timerFunc = () => {
    setImmediate(flushCallbacks);
  };
}
// 最后降级使用 setTimeout（宏任务）
else {
  timerFunc = () => {
    setTimeout(flushCallbacks, 0);
  };
}
```

**Vue 3 实现**（直接使用 Promise）：

```javascript
// Vue 3 简化实现
let currentFlushPromise = null;

export function nextTick(callback) {
  if (callback) {
    return Promise.resolve().then(callback);
  }
  return currentFlushPromise || Promise.resolve();
}
```

### 问题6：微任务和宏任务在 Vue 中如何影响性能？如何避免长任务阻塞？

**考察点**：对 Event Loop 的理解，以及性能优化的实践经验

**参考答案**：

---

#### 微任务 vs 宏任务

**执行顺序**：
```
当前调用栈 → 清空微任务队列 → 执行一个宏任务 → 清空微任务队列 → 循环...
```

**常见任务类型**：
| 类型 | 示例 | Vue 中的应用 |
|------|------|-------------|
| 微任务 | Promise.then, MutationObserver, queueMicrotask | nextTick（优先） |
| 宏任务 | setTimeout, setInterval, requestAnimationFrame | 降级方案、动画 |

**Vue 的调度策略**：
- **优先微任务**：让视图更新尽可能快
- **批量处理**：合并多个更新，减少渲染次数
- **空闲执行**：利用 `requestIdleCallback` 处理非紧急任务

---

#### 长任务问题及解决方案

**长任务（Long Task）**：执行时间超过 50ms 的任务，会导致页面卡顿

**场景1：大量数据渲染**

```vue
<template>
  <div v-for="item in largeList" :key="item.id">
    {{ item.name }}
  </div>
</template>

<script>
export default {
  data() {
    return {
      largeList: [] // 假设有 10000 条数据
    }
  },
  mounted() {
    // ❌ 一次性渲染 10000 条，主线程阻塞
    this.largeList = this.generateData(10000);
    
    // ✅ 使用分片渲染
    this.renderInChunks();
  },
  methods: {
    renderInChunks() {
      const total = 10000;
      const chunkSize = 100;
      let index = 0;
      
      const render = () => {
        const end = Math.min(index + chunkSize, total);
        const chunk = this.generateData(end - index);
        this.largeList.push(...chunk);
        index = end;
        
        if (index < total) {
          // 使用 setTimeout 让出主线程
          setTimeout(render, 0);
        }
      };
      
      render();
    }
  }
}
</script>
```

**场景2：复杂计算**

```javascript
// ❌ 同步计算，阻塞主线程
computed: {
  expensiveValue() {
    // 假设这里有复杂的计算逻辑
    return this.largeArray.map(item => item.value).reduce((a, b) => a + b, 0);
  }
}

// ✅ 使用 Web Worker 处理
// worker.js
self.addEventListener('message', (e) => {
  const result = e.data.reduce((a, b) => a + b, 0);
  self.postMessage(result);
});

// 组件中
const worker = new Worker('worker.js');
worker.postMessage(this.largeArray);
worker.onmessage = (e) => {
  this.expensiveValue = e.data;
};
```

**场景3：动画优化**

```javascript
// ❌ 使用 setTimeout 做动画，可能掉帧
function animate() {
  element.style.transform = `translateX(${x}px)`;
  x += 5;
  setTimeout(animate, 16);
}

// ✅ 使用 requestAnimationFrame，与浏览器刷新率同步
function animate() {
  element.style.transform = `translateX(${x}px)`;
  x += 5;
  requestAnimationFrame(animate);
}
```

## 四、浏览器渲染流水线

### 问题7：Vue 的组件渲染和浏览器渲染流程如何协作？什么情况下会触发重排和重绘？如何避免？

**考察点**：对浏览器渲染机制的理解，以及 Vue 中的优化实践

**参考答案**：

---

#### 浏览器渲染流水线

```
JS 执行 → Style 计算 → Layout（重排）→ Paint（重绘）→ Composite（合成）
```

**关键步骤**：
1. **Style**：计算元素的最终样式
2. **Layout（重排）**：计算元素几何位置（宽高、位置）
3. **Paint（重绘）**：填充像素
4. **Composite**：将多个图层合并

**重排触发场景**：
- 添加/删除 DOM 元素
- 改变元素位置、尺寸（`width`、`height`、`margin`、`top` 等）
- 改变窗口大小
- 读取某些属性（`offsetHeight`、`getComputedStyle`）

**重绘触发场景**：
- 改变颜色、背景、可见性等不影响布局的属性

---

#### Vue 中避免重排/重绘的实践

**1. 批量修改样式**

```javascript
// ❌ 多次触发重排
this.width = '100px';
this.height = '100px';
this.margin = '10px';

// ✅ 合并为一次（使用 class）
this.className = 'new-size';

// ✅ 或使用 cssText
element.style.cssText = 'width:100px;height:100px;margin:10px;';
```

**2. 使用 transform 代替位置属性**

```vue
<template>
  <!-- ❌ 改变 left/top 触发重排 -->
  <div :style="{ left: x + 'px', top: y + 'px' }" class="box">
    移动我
  </div>
  
  <!-- ✅ 使用 transform 只触发合成 -->
  <div :style="{ transform: `translate(${x}px, ${y}px)` }" class="box">
    移动我
  </div>
</template>
```

**3. 避免强制同步布局**

```javascript
// ❌ 强制同步布局：读取布局属性后立即修改
function resize() {
  const width = element.offsetWidth; // 读取，触发 Layout
  element.style.width = width + 10 + 'px'; // 修改，再次触发 Layout
}

// ✅ 批量读取，批量修改
function resize() {
  const width = element.offsetWidth; // 读取
  const height = element.offsetHeight; // 读取
  // 所有读取完成后，统一修改
  element.style.width = width + 10 + 'px';
  element.style.height = height + 10 + 'px';
}
```

**4. Vue 中的虚拟 DOM 批量更新**

Vue 的异步更新机制本身就起到了批量修改的作用：

```javascript
// 多次修改会被合并
this.width = 100;
this.height = 200;
this.opacity = 0.5;
// 所有这些修改只会在 nextTick 后触发一次渲染
```

**5. 使用 `will-change` 提示浏览器**

```css
/* 告知浏览器该元素即将发生变换，提前创建合成层 */
.animated {
  will-change: transform, opacity;
}
```

### 问题8：Vue 中的 `v-for` 和 `v-if` 同时使用时为什么有性能问题？如何优化？

**考察点**：对 Vue 编译原理和渲染性能的理解

**参考答案**：

---

#### 问题分析

**Vue 2**：`v-for` 优先级高于 `v-if`

```vue
<!-- ❌ 性能问题 -->
<div v-for="item in list" :key="item.id" v-if="item.isActive">
  {{ item.name }}
</div>
```

**实际渲染过程**：
```javascript
// 编译后相当于
function render() {
  return this.list.map(item => {
    // 先遍历整个列表，再判断条件
    if (item.isActive) {
      return createVNode('div', null, item.name);
    }
    return null;
  });
}
```

**问题**：
- 即使大部分数据被过滤，仍然需要遍历整个列表
- 每个项都会创建虚拟节点，造成性能浪费

**Vue 3**：`v-if` 优先级高于 `v-for`（会报错警告）

---

#### 优化方案

**1. 使用计算属性过滤数据**

```vue
<template>
  <!-- ✅ 只遍历过滤后的数据 -->
  <div v-for="item in activeList" :key="item.id">
    {{ item.name }}
  </div>
</template>

<script>
export default {
  data() {
    return {
      list: [/* ... */]
    }
  },
  computed: {
    activeList() {
      // 只在依赖变化时重新计算
      return this.list.filter(item => item.isActive);
    }
  }
}
</script>
```

**2. 将条件判断移到外层（Vue 2）**

```vue
<template>
  <!-- 如果条件不满足，整个列表都不渲染 -->
  <div v-if="showList">
    <div v-for="item in list" :key="item.id">
      {{ item.name }}
    </div>
  </div>
</template>
```

**3. 使用 `<template>` 包裹（Vue 3）**

```vue
<template>
  <!-- Vue 3 中会报错，要求分开使用 -->
  <!-- 正确做法：用 template 包裹 v-if -->
  <template v-for="item in list" :key="item.id">
    <div v-if="item.isActive">
      {{ item.name }}
    </div>
  </template>
</template>
```

## 五、实际开发中的底层原理问题

### 问题9：Vue 中 `keep-alive` 的实现原理是什么？如何管理缓存组件的生命周期？

**考察点**：对 Vue 组件缓存机制的理解，以及实际应用

**参考答案**：

---

#### keep-alive 核心原理

**缓存策略**：
- 使用 LRU（最近最少使用）算法管理缓存
- 缓存的是组件的 VNode 和 DOM 实例，而不是重新渲染

**简化实现**：

```javascript
// 简化版 keep-alive 实现
const KeepAlive = {
  props: {
    include: [String, RegExp, Array],
    exclude: [String, RegExp, Array],
    max: Number
  },
  
  setup(props, { slots }) {
    const cache = new Map();      // 缓存 VNode
    const keys = new Set();       // 缓存 key 列表
    
    // 获取当前需要缓存的组件名称
    function getComponentName(vnode) {
      return vnode.type.name;
    }
    
    // 判断是否需要缓存
    function shouldCache(name) {
      if (props.include && !matches(name, props.include)) return false;
      if (props.exclude && matches(name, props.exclude)) return false;
      return true;
    }
    
    // LRU 淘汰策略
    function pruneCacheEntry(key) {
      cache.delete(key);
      keys.delete(key);
    }
    
    return () => {
      const vnode = slots.default();
      const name = getComponentName(vnode);
      
      if (shouldCache(name)) {
        const key = vnode.key || name;
        
        if (cache.has(key)) {
          // 命中缓存，复用 VNode
          const cachedVNode = cache.get(key);
          // 标记为已激活，触发 activated 钩子
          vnode.component = cachedVNode.component;
          vnode.el = cachedVNode.el;
        } else {
          // 未命中，缓存当前 VNode
          cache.set(key, vnode);
          keys.add(key);
          
          // 超出最大缓存数，淘汰最旧的
          if (props.max && keys.size > props.max) {
            const oldestKey = keys.values().next().value;
            pruneCacheEntry(oldestKey);
          }
        }
      }
      
      return vnode;
    };
  }
};
```

---

#### 生命周期管理

**新增钩子**：
- `activated`：组件被激活时调用
- `deactivated`：组件被缓存时调用

**使用示例**：

```vue
<template>
  <keep-alive :include="['Home', 'Profile']" :max="10">
    <router-view />
  </keep-alive>
</template>

<script>
export default {
  name: 'Home', // 必须设置 name，用于 include 匹配
  activated() {
    // 组件激活时触发（首次进入也会触发）
    console.log('组件被激活');
    // 刷新数据
    this.fetchData();
  },
  deactivated() {
    // 组件被缓存时触发
    console.log('组件被缓存');
    // 保存滚动位置、清理定时器等
    this.saveScrollPosition();
  }
}
</script>
```

---

#### 实际应用场景

**1. 路由缓存**

```javascript
// router.js
export default {
  routes: [
    {
      path: '/list',
      component: List,
      meta: { keepAlive: true } // 标记需要缓存
    },
    {
      path: '/detail',
      component: Detail,
      meta: { keepAlive: false }
    }
  ]
}
```

```vue
<!-- App.vue -->
<template>
  <keep-alive>
    <router-view v-if="$route.meta.keepAlive" />
  </keep-alive>
  <router-view v-if="!$route.meta.keepAlive" />
</template>
```

**2. 动态缓存列表页**

```vue
<template>
  <keep-alive :include="cachedViews">
    <router-view />
  </keep-alive>
</template>

<script>
export default {
  data() {
    return {
      cachedViews: [] // 动态维护需要缓存的页面
    }
  },
  watch: {
    $route(to) {
      // 从详情页返回列表页时，保留列表页缓存
      if (to.name === 'List') {
        if (!this.cachedViews.includes('List')) {
          this.cachedViews.push('List');
        }
      }
      // 进入详情页时，不清除列表页缓存
    }
  }
}
</script>
```

### 问题10：Vue 中 `scoped` 样式是如何实现的？有哪些注意事项？

**考察点**：对 Vue 编译原理的理解，以及样式隔离的实现机制

**参考答案**：

---

#### scoped 实现原理

**编译过程**：
1. 为组件模板中的每个 DOM 节点添加唯一的 `data-v-xxxxx` 属性
2. 将 CSS 选择器转换为带属性选择器的形式

**示例**：

```vue
<!-- 源代码 -->
<style scoped>
.title {
  color: red;
}
</style>

<template>
  <div class="title">Hello</div>
</template>
```

```html
<!-- 编译后 -->
<style>
.title[data-v-7ba5bd90] {
  color: red;
}
</style>

<template>
  <div class="title" data-v-7ba5bd90>Hello</div>
</template>
```

---

#### 注意事项

**1. 子组件的根元素会被影响**

```vue
<!-- 父组件 -->
<template>
  <div class="parent">
    <ChildComponent />
  </div>
</template>

<style scoped>
/* 这个样式会影响子组件的根元素 */
.parent .child-class {
  color: red;
}
</style>
```

**2. 深度选择器**

```vue
<style scoped>
/* Vue 2: 使用 ::v-deep 或 /deep/ */
::v-deep .child-component .title {
  color: red;
}

/* Vue 3: 使用 :deep() */
:deep(.child-component .title) {
  color: red;
}
</style>
```

**3. 动态生成的内容**

```vue
<template>
  <!-- v-html 生成的内容不会被添加 data-v 属性 -->
  <div v-html="htmlContent"></div>
</template>

<style scoped>
/* 需要使用深度选择器 */
:deep(p) {
  color: red;
}
</style>
```

**4. 性能影响**

```vue
<!-- ❌ 大量使用深度选择器会影响性能 -->
<style scoped>
:deep(*) {
  box-sizing: border-box;
}
</style>

<!-- ✅ 使用全局样式处理通用规则 -->
<style>
* {
  box-sizing: border-box;
}
</style>
```
