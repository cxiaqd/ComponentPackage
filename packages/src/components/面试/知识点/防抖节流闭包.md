防抖（debounce）和节流（throttle）的实现必须依赖闭包，因为它们的核心需求是**在函数多次调用之间共享和持久化状态**（如定时器ID或上一次执行的时间戳），而闭包正好提供了这种“记忆”能力。

---

## 一、防抖（Debounce）与闭包

防抖的功能是：当连续触发事件时，只有在最后一次触发后的指定延迟时间内没有再次触发，才执行一次函数。

```javascript
function debounce(fn, delay) {
  let timer = null;  // 闭包变量，用于存储定时器ID
  
  return function(...args) {
    // 每次调用，清除之前的定时器
    if (timer) clearTimeout(timer);
    
    // 重新设置定时器
    timer = setTimeout(() => {
      fn.apply(this, args);
      timer = null;
    }, delay);
  };
}
```

**为什么需要闭包？**
- `timer` 变量定义在 `debounce` 函数内部，返回的函数（闭包）引用了它。
- 如果不用闭包，每次调用返回的函数时，`timer` 都会是一个全新的局部变量，无法记录上一次设置的定时器，也就无法清除它。
- 通过闭包，`timer` 在多次调用之间被**共享和持久化**，从而实现“清除上一次定时器”的逻辑。

---

## 二、节流（Throttle）与闭包

节流的功能是：在一定时间间隔内，函数只执行一次，保证执行频率。

```javascript
function throttle(fn, delay) {
  let lastTime = 0;  // 闭包变量，记录上次执行时间
  
  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= delay) {
      fn.apply(this, args);
      lastTime = now;
    }
  };
}
```

**为什么需要闭包？**
- `lastTime` 需要记录上一次执行的时间戳，以便判断是否到达节流间隔。
- 如果不使用闭包，每次调用返回的函数都会新建一个 `lastTime`，无法记录历史时间。
- 闭包让 `lastTime` 在多次调用之间保持同一个值，实现了状态跟踪。

---

## 三、如果没有闭包会怎样？

如果直接用普通函数定义，而不返回闭包：

```javascript
function debounce(fn, delay) {
  let timer = null;
  // 假设我们直接执行，而不是返回函数
  // 这样每次调用 debounce 都会重新创建 timer
  // 无法在多次触发之间共享状态
}
```

或者手动将 `timer` 挂在全局变量上：

```javascript
let timer = null; // 全局污染
function debounce(fn, delay) {
  return function(...args) {
    if (timer) clearTimeout(timer);
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
```

这样虽然也能工作，但 `timer` 变成了全局变量，会导致多个防抖函数互相干扰，且无法为每个实例独立保存状态。

---

## 四、闭包带来的好处

1. **状态私有化**：每个 `debounce` 或 `throttle` 实例拥有自己的 `timer` 或 `lastTime`，互不干扰。
2. **持久化存储**：变量在函数执行完毕后仍然存活，供后续调用使用。
3. **封装性**：调用者无需关心内部状态，只需调用返回的函数即可。
4. **避免全局污染**：状态保存在闭包内，不会影响全局命名空间。

---

## 五、总结

防抖和节流之所以必须使用闭包，是因为它们需要在**多次函数调用之间维持一个持续的状态**（如定时器ID或时间戳）。闭包通过让内部函数引用外部函数的变量，使这些变量在外部函数执行完毕后依然驻留在内存中，从而实现了状态的“记忆”和共享。如果没有闭包，就无法记录上一次调用的信息，防抖和节流也就无法正常运作。
