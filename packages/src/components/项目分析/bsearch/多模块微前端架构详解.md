# bSearch 项目技术分析

## 多模块微前端架构详解

### 1. 整体架构概述

bSearch 项目采用**多模块 + 微前端**的混合架构模式，通过将大型应用拆分为多个独立开发、独立部署的子应用，再通过微前端框架进行集成，实现代码复用和模块解耦。

**项目模块结构：**
```
bsearch-frontend/
├── search-center/          # 主应用 - 搜索中心（融合搜索、分布式检索）
├── text-image/             # 子应用 - 图文搜索模块
├── theme-config/           # 子应用 - 主题配置模块
└── ...
```

### 2. 核心技术栈

| 技术 | 版本 | 作用 |
|------|------|------|
| **hel-micro** | ^3.13.8 | 微前端核心框架，用于子应用加载和集成 |
| **Vue** | 2.7.x | 前端框架 |
| **Vuex** | ^3.1.3 | 状态管理 |
| **Vue Router** | ^3.1.6 | 路由管理 |
| **Webpack** | (via Vue CLI 4.5.0) | 构建工具 |

### 3. 微前端实现原理

#### 3.1 子应用注册与加载

每个子应用（search-center、text-image、theme-config）都通过 `hel-micro` 框架进行注册和加载。核心代码位于各子应用的 `main.js` 入口文件中：

```javascript
// bsearch-frontend/search-center/src/main.js
import { preFetchLib, bindExternals } from 'hel-micro';

// 1. 绑定外部依赖（Vue、HUI 组件库）
bindExternals({ vue: Vue, hui: hui });

// 2. 预加载远程子应用模块
(async function() {
  const mod = await preFetchLib('remote-selection-point', {
    async getSubAppAndItsVersionFn() {
      // 自定义元数据获取请求
      const res = await fetch('/imap-server/selection/remote-selection-point/hel-meta.json');
      if (res.status !== 200) {
        Vue.use(selectionPointPro);
        store.commit('setSelecetionOline', false);
      }
      const meta = await res.json();
      return meta;
    },
    skip404Sniff: true
  });
  Vue.use(mod);
  store.commit('setInstall', true);
})().catch(err => {
  console.error('loadApp err: ', err);
});
```

**工作流程：**
1. **bindExternals**: 将 Vue、HUI 等公共库暴露为外部依赖，避免重复加载
2. **preFetchLib**: 从远程服务器预加载子应用模块
3. **getSubAppAndItsVersionFn**: 自定义函数，动态获取子应用的元数据（版本、入口文件等）
4. **Vue.use(mod)**: 将加载的子应用注册为 Vue 插件

#### 3.3 模块间通信机制

**a) 通过 Event Bus 进行通信:**

在每个子应用的 `main.js` 中创建全局 Event Bus：
```javascript
Vue.prototype.bus = new Vue();
```

组件间通过 `$emit` 和 `$on` 进行通信：
```javascript
// 发送事件
this.bus.$emit('changeWidth');
this.bus.$emit('fullLoading', data);
this.bus.$emit('handleBall', { imgData, event });

// 监听事件
this.bus.$on('closePlayer', () => { ... });
```

**b) 通过 Vuex 共享状态:**

主应用和子应用共享部分 Vuex 状态：
```javascript
// store/index.js
export default new Vuex.Store({
  state,
  actions,
  mutations,
  modules: {
    fusion,      // 融合搜索模块
    popWindow,   // 弹窗模块
    targetTrace, // 目标追踪模块
    mapOld,      // 地图模块
    distributed  // 分布式检索模块
  }
});
```

**c) 通过 LocalStorage 共享状态:**

例如选点组件的在线状态：
```javascript
localStorage.setItem('selectionPoint-online-bsearch', 1); // 在线
localStorage.setItem('selectionPoint-online-bsearch', 0); // 离线
```

### 4. 远程组件加载机制

项目使用了 `remote-selection-point` 远程选点组件，通过 hel-micro 框架动态加载：

```javascript
// 1. 导入 UMD 版本作为降级方案
import selectionPointPro from 'remote-selection-point/lib/selection-point-pro.umd.min';
import 'remote-selection-point/lib/selection-point-pro.css';

// 2. 尝试动态加载远程模块
const mod = await preFetchLib('remote-selection-point', {
  async getSubAppAndItsVersionFn() {
    const res = await fetch('/imap-server/selection/remote-selection-point/hel-meta.json');
    if (res.status !== 200) {
      // 降级：使用本地 UMD 版本
      Vue.use(selectionPointPro);
      store.commit('setSelecetionOline', false);
      return;
    }
    const meta = await res.json();
    return meta;
  }
});
Vue.use(mod);
```
**UMD** 是 **Universal Module Definition**（通用模块定义）的缩写。

结合你给出的文件名 `selection-point-pro.umd.min`，它表示这是一个**通用模块格式的、已压缩的、生产环境版本**的库文件。具体含义拆解如下：

### 1. UMD（通用模块定义）
UMD 是一种兼容多种模块化规范的打包格式。这个文件既可以在浏览器中直接通过 `<script>` 标签引入（挂载到全局变量），也可以兼容 CommonJS（Node.js 环境）和 AMD（如 RequireJS）等模块化规范。

简单来说，无论你的项目是直接用原生 HTML、还是用 Webpack/Vite 等构建工具，这个文件都能正常工作。

### 2. pro（专业版/增强版）
`pro` 通常代表 **Professional**，在组件库命名中，这通常意味着这是该库的**增强版**或**专业版**，相比基础版包含更多功能、更复杂的交互逻辑或更完整的业务场景组件。

### 3. min（压缩/生产环境）
`min` 是 **minified** 的缩写。这个文件经过了代码压缩（去除了空格、注释，混淆了变量名），文件体积更小，加载速度更快，适合部署到线上生产环境。对应的，开发调试时通常会使用未压缩的 `.umd.js` 或 `.umd.development.js` 版本。

### 总结
这是一个名为 `selection-point-pro` 的组件库的**UMD打包格式的生产环境压缩包**。

**使用场景**：如果你是在一个简单的 HTML 页面中使用该组件，通常需要通过 `<script src=".../selection-point-pro.umd.min.js"></script>` 的方式引入，之后该组件会暴露为一个全局变量供你调用。

**降级策略：**
- 如果远程加载失败（HTTP 404 或其他错误），自动降级使用本地 UMD 版本
- 通过 `store.commit('setSelecetionOline', false)` 标记当前为离线模式

### 12. hel-micro 框架核心 API 说明

#### 12.1 bindExternals

**作用：** 绑定外部依赖，让子应用可以使用主应用已加载的公共库。

```javascript
bindExternals({
  vue: Vue,      // 暴露 Vue 构造函数
  hui: hui       // 暴露 HUI 组件库实例
});
```

**原理：** hel-micro 会将这些外部依赖注册到全局依赖表中，当子应用请求这些依赖时，直接从主应用获取，而不是重新加载。

#### 12.2 preFetchLib

**作用：** 预加载远程子应用模块。

```javascript
const mod = await preFetchLib('remote-selection-point', {
  async getSubAppAndItsVersionFn() {
    // 自定义元数据获取逻辑
    const res = await fetch('/imap-server/selection/remote-selection-point/hel-meta.json');
    const meta = await res.json();
    return meta;
  },
  skip404Sniff: true  // 跳过 404 检测
});
```

**参数说明：**
- 第一个参数：子应用名称（模块名）
- 第二个参数：配置对象
  - `getSubAppAndItsVersionFn`: 自定义获取子应用元数据的函数
  - `skip404Sniff`: 是否跳过 404 检测

**元数据结构 (hel-meta.json):**
```json
{
  "name": "remote-selection-point",
  "version": "0.1.23",
  "umdUrl": "/path/to/remote-selection-point.umd.min.js",
  "cssUrl": "/path/to/remote-selection-point.css",
  "externals": ["vue", "hui"]
}
```

### 15. 常见问题与解决方案

#### 15.1 远程模块加载失败

**问题：** 远程模块元数据请求失败（404 或网络错误）

**解决方案：**
```javascript
const mod = await preFetchLib('remote-selection-point', {
  async getSubAppAndItsVersionFn() {
    try {
      const res = await fetch('/imap-server/selection/remote-selection-point/hel-meta.json');
      if (res.status !== 200) {
        throw new Error('HTTP ' + res.status);
      }
      return await res.json();
    } catch (err) {
      // 降级处理
      console.error('远程加载失败，使用本地版本:', err);
      return null;
    }
  },
  skip404Sniff: true
});

// 如果 mod 为 null，使用本地 UMD 版本
if (!mod) {
  Vue.use(selectionPointPro);
} else {
  Vue.use(mod);
}
```

#### 15.2 样式冲突

**问题：** 多个子应用的样式可能冲突

**解决方案：**
- 每个子应用使用独立的主题入口文件
- 使用 CSS Modules 或 Scoped CSS
- 统一使用 HUI 组件库的设计规范

#### 15.3 状态同步问题

**问题：** 子应用间状态不同步

**解决方案：**
- 使用统一的 Vuex 模块管理共享状态
- 通过 Event Bus 进行状态变更通知
- 使用 LocalStorage 持久化关键状态
