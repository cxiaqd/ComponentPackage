## 项目名称：智能融合搜索平台（安防领域）

### 项目背景： 公司自 2020 年起持续迭代的核心产品，面向安防监控领域，提供人脸/人体/车辆多目标融合检索、目标检测建模、视频轨迹研判等功能。我于 2022 年入职后深度参与，主要负责核心业务模块的研发与性能优化。

### 核心贡献：
**架构演进与性能优化**：针对首屏加载慢、列表渲染卡顿等问题，实施路由懒加载、虚拟滚动、Webpack 分包策略（Gzip、Tree Shaking、SplitChunks），将首屏加载时间从 3.2s 降至 1.5s 以内。
**复杂业务模块交付**：独立负责智图研判模块的迭代，实现融合搜索、专项搜索、人体部件搜索等功能；封装图片上传检测、地图选点、轨迹回放等 20+ 业务组件，支撑多场景快速复用。
**微前端落地**：参与引入 hel-micro 实现模块联邦，支持子模块独立开发部署，解决代码耦合问题，团队并行开发效率提升约 50%。
**工程化建设**：推动 ESLint + Prettier + Husky 规范落地，建立 Git 提交规范与自动化 changelog；基于 Jest 对核心工具函数进行单元测试，保障代码质量。
**智图研判模块开发**:负责融合搜索、专项搜索（侧脸/背影/体态）、人体部件搜索（鞋帽背包）等核心功能开发，通过 Vuex 模块化管理搜索结果、分页、筛选条件等状态。
**目标检测建模链路**:实现图片上传→目标检测→目标选择→特征建模→一键搜图完整流程，支持人脸/人体/车辆/非机动车等 8 种目标类型，处理检测无目标、建模失败等异常场景。
**API 层封装与优化**:封装 30+ 业务接口，统一错误处理和 CSRF 防护；优化冷数据任务轮询机制，支持任务状态实时刷新。
**性能优化与问题修复**:通过路由懒加载、组件异步加载优化首屏性能；解决播放器弹窗遮挡、检测建模超时等 10+ 线上问题。
**组件复用与维护**:抽象通用方法到 mixins（quickSearch），降低重复代码；维护路由配置、国际化语言包，支撑多业务线接入。
**项目成果**  
支撑公司内部 5+ 业务线接入；一键搜图功能使目标检索效率提升 60%；修复的崩溃恢复机制将播放器可用性提升至 99.5%

| 考察点 | 话术要点 |

| **接手后做了哪些改进** | 重构了检测建模的错误处理逻辑，增加了重试机制和友好提示；优化了冷数据任务轮询，避免无效请求；补充了关键代码注释和接口文档 |

### 二、业务理解类

| 考察点 | 话术要点 |
|--------|---------|
| **智图研判是什么** | 融合人脸、人体、车辆、非机动车等多种目标的智能检索系统。用户可以上传一张包含多个目标的图片，系统自动检测出所有目标，用户选择后即可按目标类型分别检索 |
| **专项搜索有哪些** | 侧脸搜人（人脸侧脸角度检测）、背影搜人（人体背影识别）、体态搜索（基于体态特征检索）、人体部件搜索（鞋子/帽子/背包） |
| **检测建模流程** | 调用检测接口获取目标位置和置信度 → 用户选择目标 → 调用建模接口提取特征向量 → 携带模型值跳转搜索结果页；建模失败时有降级提示 |

### 三、技术实现类

| 考察点 | 话术要点 |
|--------|---------|
| **多目标类型如何兼容** | 后端返回的数据结构不同（face 用 recommendFaceRect，vehicle 有 license），我在 `cauTargetList` 方法中统一处理，不同类型走不同分支，最终输出标准化对象 |
| **目标选择组件怎么实现的** | 使用 `@isearchui-pro/target-img-upload` 组件，传入检测结果和配置参数，监听 `on-confirm` 事件获取用户选择的目标列表 |
| **冷数据任务怎么做的** | 创建任务后返回 taskId，前端轮询 `coldTaskStatus` 接口，状态为完成时调用 `coldTaskResult` 获取结果；支持任务插队和删除 |
| **视频搜索跳转怎么实现** | 封装 `goToVideo` 方法，通过顶层 `goToApp` 跨应用通信，传递模型值或车牌参数；支持带坐标的精准搜索和车牌关键字搜索 |

### 四、问题解决类

| 考察点 | 话术要点 |
|--------|---------|
| **遇到过最复杂的 Bug** | 检测建模弹窗被视频播放器遮挡。排查发现播放器设置了高 zIndex，我在弹窗显示后动态添加 `hikcc_cover="opaque"` 属性并调整 zIndex，同时处理了全屏模式下的兼容问题 |
| **检测建模超时怎么处理** | 增加超时重试机制，loading 状态延长给用户明确反馈；失败时根据错误码展示不同提示（“图片质量低”或“检测不出目标”），避免用户困惑 |
| **如何保证建模成功率** | 前端做图片格式和大小校验；调用接口前转换 URL 格式；建模失败时给出明确提示，不影响用户继续使用 |

## 面试话术示例

**问：介绍一下你在 bsearch-frontend 项目中做的工作**

> 我主要负责智图研判模块和目标检测建模链路的开发。智图研判是项目的核心功能，支持用户上传图片后自动检测人脸、人体、车辆等目标，选择后跳转到对应类型进行检索。
>
> 具体工作包括：实现检测建模的完整流程，处理检测无目标、建模失败等异常场景；封装统一的 API 请求层，对接 30+ 业务接口；优化冷数据任务轮询机制；解决播放器弹窗遮挡、检测超时等线上问题。
>
> 虽然不是项目初始成员，但接手后深入理解了整体架构，并主导了多个子模块的迭代。通过重构错误处理逻辑和补充文档，降低了团队维护成本。

**问：检测建模过程中遇到过什么问题？怎么解决的？**

> 主要遇到过两个问题：一是建模接口超时，用户长时间等待后失败体验很差；二是检测结果弹窗被视频播放器遮挡。
>
> 针对超时问题，我增加了超时重试机制，并延长 loading 状态，给用户明确反馈；同时根据后端返回的错误码展示不同提示（如“图片质量低”），避免用户困惑。
>
> 针对弹窗遮挡问题，我分析了播放器的层级结构，在弹窗显示后动态添加 `hikcc_cover` 属性并调整 zIndex，同时处理了全屏模式下的兼容情况。
