#### 二、技术实现类

| 考察点 | 话术要点 |
|--------|---------|
| **插件化组件如何实现** | 组件提供 install 方法，内部注册依赖组件和主组件；支持 withInstall 高阶函数批量注册；支持按需引入，业务层可按需加载减少包体积 |
| **组件如何支持按需加载** | 每个组件独立导出，业务层可以通过 `import RightDetailPro from '@isearchui-pro/comp-v1/src/right-detail-pro'` 单独引入；配合 babel-plugin-import 实现自动按需加载 |
| **工具函数库如何设计** | 按功能分类导出（base/dom/event/test），使用 ES Module 支持 Tree Shaking；深拷贝使用 WeakMap 处理循环引用，支持 Date/RegExp 特殊对象 |
| **主题换肤怎么实现** | 通过 CSS 变量定义主题色，动态加载主题 CSS 文件；localStorage 存储用户偏好；切换时修改 body className，无需刷新页面 |
| **国际化怎么实现** | 基于 vue-i18n，语言包按模块拆分；生产环境通过 axios 动态加载，开发环境本地 require；hui 组件库语言同步切换 |

#### 三、问题解决类

| 考察点 | 话术要点 |
|--------|---------|
| **遇到过最复杂的 Bug** | 深拷贝函数在处理循环引用对象时栈溢出。排查后发现原实现未处理循环引用，改用 WeakMap 缓存已拷贝对象，递归时检测到循环直接返回缓存，解决了问题 |
| **Sass 版本冲突怎么解决** | 项目中多个子包依赖不同 sass 版本，导致编译报错。通过 pnpm overrides 统一锁定 sass 版本为 ~1.58.3，同时配置 `sass-loader>sass` 确保传递版本一致 |
| **组件样式被全局样式覆盖** | 主题切换时组件样式优先级不够。采用 BEM 命名规范提高样式权重，关键组件使用 `scoped` 隔离，避免全局污染 |

Q1：为什么选择 Monorepo？解决了什么问题？
解决 40+ 组件包版本管理混乱、依赖冲突问题。通过 pnpm workspace 统一管理，支持组件独立发布和本地联调，使用 workspace:* 协议保证依赖一致性。
Q2：插件化组件是如何实现的？有什么好处？
设计了 4 种插件模式：简单插件、带依赖插件、高阶函数插件、批量导出。好处：按需加载、依赖自动注册、Tree Shaking 友好。
Q3：主题换肤方案是怎么实现的？
通过 CSS 变量定义主题色，localStorage 存储用户选择。切换时动态加载对应主题 CSS 文件，修改 body className，无需刷新页面。
Q4：Tree Shaking 在项目中是如何生效的？
组件库使用 ES Module 导出，package.json 配置 sideEffects: false，构建工具自动进行死代码消除。工具函数库按函数导出，未使用的函数不会打包。
Q5：遇到了哪些技术难点？如何解决的？
Sass 版本冲突：通过 pnpm overrides 锁定版本
循环引用问题：深拷贝使用 WeakMap 检测
跨包调试：pnpm workspace 实现本地软链接
